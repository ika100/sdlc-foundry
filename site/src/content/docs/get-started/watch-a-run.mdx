One system, recorded in one run from an empty folder to prod. **Part 1** (steps 1–4) creates the repos and a local cluster and ships a first endpoint to dev. **Part 2** (steps 5–7) adds a Postgres database and a Next.js web UI with one system spec shipped across three repos. **Part 3** (steps 8–12) adds staging, observability, a release from the tested builds, prod with daily backups, and a restore drill. Each part runs in a fresh Claude Code session (`/clear`): every command keeps its state in the repos. Every step is one sentence in Claude Code: say what you want in your own words and Claude runs the matching slash command, or type the command yourself. Each step shows both. Open a step to jump the recording there and see what was typed, what Claude asked, what it did and the result. Each step links to the real pull requests in the public demo repos [taskboard13-api](https://github.com/ika100-demo/taskboard13-api), [taskboard13-web](https://github.com/ika100-demo/taskboard13-web) and [taskboard13-gitops](https://github.com/ika100-demo/taskboard13-gitops), so you can check every claim.

## About the timing

Every time on this page is wall-clock time with CI rounds included. Nobody watched this run: Claude Code typed the sentences and took the suggested answer to the three questions the run asked, so a person's time is the 3 minutes those answers and the gaps until the next sentence took. **Part 1 took 31 minutes, part 2 49 and part 3 33**, 113 in all; the recording shows them in 4 minutes. Earlier runs, and what changed in the platform between them, are in [Performance measurements](/sdlc-foundry/reference/performance/).

**What was edited:** waiting is cut and the host name in the status bar is blanked. Nothing else is changed. The journey was recorded with [asciinema](https://asciinema.org) on 2026-11-13 with sdlc-foundry 5.21.0, in the public demo organisation [ika100-demo](https://github.com/ika100-demo); Claude Code typed the sentences on the user's behalf in the same recorded terminal.

## Background: timing in detail

All times are minutes, measured from the recording, the journey record (`cplat platform runs journey`), the session transcripts and the GitHub Actions runs of the demo repos. The platform's goal is a journey of 60 minutes ([spec 136](https://github.com/ika100/sdlc-foundry/pull/489)).

**Per step:**

| # | Step | Minutes | Agents working | Waiting | Tokens | What takes the time |
|---|---|---|---|---|---|---|
| 1 | Create the system | 3.6 | 3.3 | 0 | 0.3 M | two repos from their templates |
| 2 | Merge, cluster and expose | 2.4 | 1.2 | 0.8 | 0.6 M | two CI rounds; the cluster start went on in the background into step 3 |
| 3 | Write and approve the spec | 4.5 | 2.4 | 1.5 | 1.2 M | the approval with 10 assumptions, the exposure check left from step 2, one CI round |
| 4 | Ship the spec | 20.1 | 12.5 | 7.6 | 7.4 M | plan, acceptance tests, coders, a mutation check, one PR, deploy and smoke |
| 5 | Add a web UI | 5.0 | 1.4 | 3.4 | 0.6 M | a new repo from its template, one CI round, a deploy |
| 6 | One spec for the whole system | 4.7 | 2.5 | 1.7 | 1.3 M | one question (no login), the approval with 9 assumptions, one CI round |
| 7 | Plan and ship it to dev | 39.4 | 28.7 | 10.7 | 17.8 M | the plan, two repo sessions building in parallel (one test run hung for 9 minutes), one landing, deploy and smoke |
| 8 | Hosts, observability and staging | 9.0 | 2.2 | 6.6 | 1.3 M | four PRs, staging promotion and smoke |
| 9 | Release | 5.2 | 2.0 | 2.9 | 1.2 M | tags on the staging commit, two follow-up PRs; no local gates, CI already passed them |
| 10 | Backups and the prod PR | 4.8 | 1.1 | 3.5 | 1.1 M | the backups bucket and the daily backup, one prod PR for both components |
| 11 | Prod | 7.9 | 0.7 | 6.9 | 0.7 M | the prod PR updated and checked again, Argo CD rolling out, smoke, the "Prod check" task |
| 12 | Restore drill | 6.0 | 0.6 | 5.4 | 0.9 M | the restored copy (3 minutes of waiting for it), the query, the discard |

Tokens per step count every session of the run: the three sessions that typed the sentences, their subagents and the repo sessions of the system ship.

**Where the wall clock went** (each minute counted once, from the session transcripts; agent work counts first):

| Share | Minutes |
|---|---|
| A person | 3 (3 %): the answers to three questions and the gaps until the next sentence |
| Waiting, no agent working | 51 (45 %): CI checks and merges 23, deploys, Argo CD and smoke 17, promotions 3.8, restores 3.1, unexplained 4.4 |
| Agents working | 59 (52 %): the sessions that typed the sentences 37, the system ship's repo sessions and subagents 22 |

**CI, as GitHub measured it:** 159 Actions runs (1 failed), 119 minutes of run time summed and 6 minutes in queues; CI was running during 49 of the 113 minutes.

**Tokens:** 35 M in 661 API calls: 34.3 M read (95 % of them from the cache) and 0.30 M written by the models; about $17 at Claude API list prices. The sessions that typed the sentences ran on Claude Opus 5.5. "Plan and ship it to dev" used half of them.

**What the run found:** five platform defects, none of which stopped the run: the build check looks for a commit subject the tester does not write ([#724](https://github.com/ika100/sdlc-foundry/issues/724)); recording the review's findings refuses a task the plan merged into another ([#725](https://github.com/ika100/sdlc-foundry/issues/725)); the observability command does not print where Grafana answers ([#726](https://github.com/ika100/sdlc-foundry/issues/726)); the web release's version command refuses an uncommitted changelog ([#727](https://github.com/ika100/sdlc-foundry/issues/727)); and the service template has no per-test time limit, so one hung test cost 9 minutes ([#728](https://github.com/ika100/sdlc-foundry/issues/728)). Spec 197 fixes all five. Not a defect, but worth watching: Claude ended the second sentence while the cluster was still starting in the background.
