One system, recorded in one run from an empty folder to prod. **Part 1** (steps 1–4) creates the repos and a local cluster and ships a first endpoint to dev. **Part 2** (steps 5–7) adds a Postgres database and a Next.js web UI with one system spec shipped across three repos. **Part 3** (steps 8–12) adds staging, observability, a release from the tested builds, prod with daily backups, and a restore drill. Each part runs in a fresh Claude Code session (`/clear`): every command keeps its state in the repos. Every step is one sentence in Claude Code: say what you want in your own words and Claude runs the matching slash command, or type the command yourself. Each step shows both. Open a step to jump the recording there and see what was typed, what Claude asked, what it did and the result. Each step links to the real pull requests in the public demo repos [taskboard6-api](https://github.com/ika100-demo/taskboard6-api), [taskboard6-web](https://github.com/ika100-demo/taskboard6-web) and [taskboard6-gitops](https://github.com/ika100-demo/taskboard6-gitops), so you can check every claim.

## About the timing

Every time on this page is wall-clock time with CI rounds included. Nobody watched this run: Claude Code typed the sentences and took the suggested answer to the three questions the run asked, so a person's time is the 4 minutes those answers and the gaps until the next sentence took. **Part 1 took about 37 minutes, part 2 about 68 and part 3 about 60**, 164 in all; the recording shows them in under 5 minutes. Every measured journey, with its time, tokens and a person's share, is in [Performance measurements](/sdlc-foundry/reference/performance/).

**What was edited:** waiting is cut and the host name in the status bar is blanked. Nothing else is changed. The journey was recorded with [asciinema](https://asciinema.org) on 2026-11-07 with sdlc-foundry 5.13.0, in the public demo organisation [ika100-demo](https://github.com/ika100-demo); Claude Code typed the sentences on the user's behalf in the same recorded terminal.

## Background: timing in detail

Nothing was blocked: for the first time no step stopped for a platform problem, and the wall clock (164) equals the working time, against 230 in journey 5. The run used 40 M tokens, 13 % fewer than journey 5. The specs now decide their defaults themselves and show them at approval (spec 149), so the run asked 3 questions instead of 20. Part 1 halved (37 minutes instead of 64): GitHub and git calls that hit a dropped network run again by themselves (spec 148). Parts 2 and 3 were slower than in journey 5: the web repo spec came out at 14 criteria, the API build's coders ran one after the other, and the prod database and a missing restore point each cost a second round. The platform's goal is a journey of 60 minutes ([spec 136](https://github.com/ika100/sdlc-foundry/pull/489)); this is the sixth measured run. Every journey, with its time, tokens, a person's share, its quality and what changed in the platform since the one before, is tracked in [Performance measurements](/sdlc-foundry/reference/performance/).

Five things are worth fixing, each named in its step; none stopped the run. They are filed for the next round (see Performance measurements).

For comparison and discussion; all journeys side by side are in [Performance measurements](/sdlc-foundry/reference/performance/). All times are minutes, measured from the recording, the journey record (`cplat platform runs journey`), the session transcripts and the GitHub Actions runs of the demo repos.
