One system, recorded in one run from an empty folder to prod. **Part 1** (steps 1–4) creates the repos and a local cluster and ships a first endpoint to dev. **Part 2** (steps 5–7) adds a Postgres database and a Next.js web UI with one system spec shipped across three repos. **Part 3** (steps 8–12) adds staging, observability, a release from the tested builds, prod with daily backups, and a restore drill. Each part runs in a fresh Claude Code session (`/clear`): every command keeps its state in the repos. Every step is one sentence in Claude Code: say what you want in your own words and Claude runs the matching slash command, or type the command yourself. Each step shows both. Open a step to jump the recording there and see what was typed, what Claude asked, what it did and the result. Each step links to the real pull requests in the public demo repos [taskboard5-api](https://github.com/ika100-demo/taskboard5-api), [taskboard5-web](https://github.com/ika100-demo/taskboard5-web) and [taskboard5-gitops](https://github.com/ika100-demo/taskboard5-gitops), so you can check every claim.

## About the timing

Every time on this page is wall-clock time with CI rounds included. Nobody watched this run: Claude Code typed the sentences and took the suggested answer to every question, so a person's time is only the 2 minutes those answers took. **Part 1 took about 64 minutes, part 2 about 56 and part 3 about 46**, 166 in all; the recording shows them in under 6 minutes. Not counted: 65 minutes in step 4 while two platform defects the run found were fixed and released to it ([#537](https://github.com/ika100/sdlc-foundry/pull/537), [#538](https://github.com/ika100/sdlc-foundry/pull/538)). The working time equals journey 4's (164), but for different reasons: parts 2 and 3 took 102 minutes instead of 133, while part 1 lost about 20 minutes to a network that kept dropping, in places where the platform did not retry. The run used 46 M tokens, 40 % fewer than journey 4: a fresh session per part, and repo specs the system plan writes (spec 147). The platform's goal is a journey of 60 minutes ([spec 136](https://github.com/ika100/sdlc-foundry/pull/489)); this is the fifth measured run. Every journey, with its time, tokens, a person's share, its quality and what changed in the platform since the one before, is tracked in [Performance measurements](/sdlc-foundry/reference/performance/).

Nine things went wrong in the platform; each is named in its step. Two were fixed during the run ([#536](https://github.com/ika100/sdlc-foundry/issues/536) with [#537](https://github.com/ika100/sdlc-foundry/pull/537), and [#538](https://github.com/ika100/sdlc-foundry/pull/538)), the rest are filed ([#539](https://github.com/ika100/sdlc-foundry/issues/539) to [#545](https://github.com/ika100/sdlc-foundry/issues/545)). Five of them stopped the run: three network drops the platform did not retry or resume from (steps 1 and 3), and the two defects fixed during step 4. Part 2 and part 3 ran without a stop.

**What was edited:** waiting is cut and the host name in the status bar is blanked. Nothing else is changed. The journey was recorded with [asciinema](https://asciinema.org) on 2026-11-06 with sdlc-foundry 5.12.0, in the public demo organisation [ika100-demo](https://github.com/ika100-demo); Claude Code typed the sentences on the user's behalf in the same recorded terminal.

## Timing in detail

For comparison and discussion; all journeys side by side are in [Performance measurements](/sdlc-foundry/reference/performance/). All times are minutes, measured from the recording, the journey record (`cplat platform runs journey`), the session transcript and the GitHub Actions runs of the demo repos.

**Per step** (journey 5, 5.12.0, against journey 4, 5.11.0):

| # | Step | Journey 5 | Journey 4 | What takes the time in journey 5 |
|---|---|---|---|---|
| 1 | Create the system | 7 | 2 | a network drop while creating the API repo, two resumes |
| 2 | Merge, cluster and expose | 10 | 2 | the cluster, two CI rounds, an Argo CD refresh after a repo-server timeout |
| 3 | Write and approve the spec | 13 | 7 | 7 questions and the approval, a second `spec land` after a network drop |
| 4 | Ship the spec | 33 (+ 65 blocked) | 21 | plan, acceptance tests, two coders, the one-replica gitops PR and the API PR, deploy and smoke |
| 5 | Add a web UI | 7 | 7 | a new repo from its template, one CI round, dev deploy |
| 6 | One spec for the whole system | 6 | 6 | 7 questions and the approval, one CI round |
| 7 | Plan and ship it to dev | 43 | 65 | plan with the repo criteria, two builds in parallel, PRs and CI, one landing, deploy and smoke |
