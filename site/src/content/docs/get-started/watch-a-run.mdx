One system, recorded in one run from an empty folder to prod. **Part 1** (steps 1–4) creates the repos and a local cluster and ships a first endpoint to dev. **Part 2** (steps 5–7) adds a Postgres database and a Next.js web UI with one system spec shipped across three repos. **Part 3** (steps 8–12) adds staging, observability, a release from the tested builds, prod with daily backups, and a restore drill. Each part runs in a fresh Claude Code session (`/clear`): every command keeps its state in the repos. Every step is one sentence in Claude Code: say what you want in your own words and Claude runs the matching slash command, or type the command yourself. Each step shows both. Open a step to jump the recording there and see what was typed, what Claude asked, what it did and the result. Each step links to the real pull requests in the public demo repos [taskboard12-api](https://github.com/ika100-demo/taskboard12-api), [taskboard12-web](https://github.com/ika100-demo/taskboard12-web) and [taskboard12-gitops](https://github.com/ika100-demo/taskboard12-gitops), so you can check every claim.

## About the timing

Every time on this page is wall-clock time with CI rounds included. Nobody watched this run: Claude Code typed the sentences and took the suggested answer to the four questions the run asked, so a person's time is the 3 minutes those answers and the gaps until the next sentence took. **Part 1 took 35 minutes (6 of them restarting Docker on the laptop), part 2 37 and part 3 38**, 109 in all; the recording shows them in 4 minutes. Earlier runs, and what changed in the platform between them, are in [Performance measurements](/sdlc-foundry/reference/performance/).

**What was edited:** waiting is cut and the host name in the status bar is blanked. Nothing else is changed. The journey was recorded with [asciinema](https://asciinema.org) on 2026-11-13 with sdlc-foundry 5.20.0, in the public demo organisation [ika100-demo](https://github.com/ika100-demo); Claude Code typed the sentences on the user's behalf in the same recorded terminal.

## Background: timing in detail

All times are minutes, measured from the recording, the journey record (`cplat platform runs journey`), the session transcripts and the GitHub Actions runs of the demo repos. The platform's goal is a journey of 60 minutes ([spec 136](https://github.com/ika100/sdlc-foundry/pull/489)).

**Per step:**

| # | Step | Minutes | Agents working | Waiting | Tokens | What takes the time |
|---|---|---|---|---|---|---|
| 1 | Create the system | 2.7 | 2.5 | 0 | 0.3 M | two repos from their templates |
| 2 | Merge, cluster and expose | 11.9 | 0.9 | 10.7 | 0.7 M | the cluster, started twice after Docker stopped (8.5), two CI rounds |
| 3 | Write and approve the spec | 4.2 | 2.0 | 1.6 | 1.4 M | one question (authentication), the approval with 7 assumptions, one CI round |
| 4 | Ship the spec | 16.5 | 10.2 | 6.3 | 8.3 M | plan, acceptance tests, coders, a mutation check, one PR, deploy and smoke |
| 5 | Add a web UI | 6.4 | 1.8 | 4.4 | 0.6 M | a new repo from its template, one CI round, a deploy |
| 6 | One spec for the whole system | 30.1 | 26.4 | 3.0 | 16.2 M | the approval, then the whole plan and system ship: two repo sessions building in parallel, one landing, deploy and smoke |
| 7 | Plan and ship it to dev | 0.3 | 0.2 | 0.1 | 0.1 M | nothing left: step 6 already shipped it |
| 8 | Hosts, observability and staging | 6.5 | 1.1 | 5.2 | 1.4 M | four PRs, staging promotion and smoke |
| 9 | Release | 5.8 | 2.1 | 3.5 | 1.4 M | tags on the staging commit, two follow-up PRs; no local gates, CI already passed them |
| 10 | Backups and the prod PR | 5.4 | 0.6 | 4.4 | 1.3 M | the backups bucket and the daily backup, one prod PR for both components |
| 11 | Prod | 8.7 | 0.2 | 8.2 | 0.6 M | the prod PR updated and checked again, Argo CD rolling out, smoke, the "Prod check" task |
| 12 | Restore drill | 10.9 | 0.5 | 10.4 | 0.9 M | an on-demand backup, the restored copy (8.2 minutes of waiting for it), the check, the discard |

Tokens per step count every session of the run: the three sessions that typed the sentences, their subagents and the repo sessions of the system ship.

**Where the wall clock went** (each minute counted once, from the session transcripts; agent work counts first):

| Share | Minutes |
|---|---|
| A person | 3 (3 %): the answers to four questions and the gaps until the next sentence |
| Waiting, no agent working | 58 (53 %): CI checks and merges 21, deploys and Argo CD 14.5, the cluster 8.5 (6 of them Docker on the laptop), restores 8.4, promotions 3.1, unexplained 3 |
| Agents working | 49 (44 %): the sessions that typed the sentences 39, the system ship's repo sessions and subagents 10 |

**CI, as GitHub measured it:** 163 Actions runs (1 failed), 105 minutes of run time summed and 6 minutes in queues; CI was running during 44 of the 109 minutes.

**Tokens:** 33 M in 579 API calls: 33.0 M read (97 % of them from the cache) and 0.27 M written by the models; about $21 at Claude API list prices. The sessions that typed the sentences ran on Claude Fable 5.2, the default model that day (journey 11 ran on Opus 5.5), which costs more per token, so the run cost more than journey 11 with fewer tokens. "One spec for the whole system" used half of them, because it shipped the system spec too.

**What the run found:** a system ship wait longer than the agent's 10-minute command limit moved to the background, and the coordinator then waited on it with a loop that matched itself (fixed by spec 194); checking a restored copy still needs a direct `kubectl` query ([#683](https://github.com/ika100/sdlc-foundry/issues/683)). Neither stopped the run.
