# Performance measurements

Every full run of the journey on [Watch a real run](https://ika100.github.io/sdlc-foundry/get-started/watch-a-run/) is measured the same way and recorded here: how long it took, how many tokens it used, how much of a person it needed, how good the result was, and what changed in the platform since the run before. The journey is always the same: an empty folder → a Python API in dev → Postgres and a Next.js web UI → staging, a release, prod with daily backups and a restore drill, in the public demo organisation [ika100-demo](https://github.com/ika100-demo). Its goal is 60 minutes ([spec 136](specs/136-the-whole-journey-fits-a-time-budget/spec.md)).

Add a row to every table below for each new journey (see [Recording a journey](#recording-a-journey)); never change the rows of an earlier one.

## Recording a journey

Do this for every full journey, and add its rows here in the same PR that updates Watch a real run.

1. **Before:** release the platform, update the plugins, and pick new demo repo names (`taskboardN-*`; earlier repos stay as evidence). Start a journey record: `cplat platform runs journey begin`.
2. **During:** record the session with asciinema, one chapter marker per step; mark each stage with `cplat platform runs journey stage <id> start|end`, a person's decisions with `journey wait person add --minutes M` and every PR with `journey pr <url> --stage <id>`. Note every platform defect when it happens.
3. **After:** `cplat platform runs journey end --outcome done`, then measure:

   ```bash
   cplat platform runs journey measure ~/.claude/projects/<dir>/<session-id>[,<session-id>...] <start> <end> \
     ika100-demo/<system>-gitops ika100-demo/<system>-api ika100-demo/<system>-web --steps <steps.tsv> --journey <run_id>
   ```

   Then, while the cluster still runs, take the screenshots of what the run built (web UI, API docs, Argo CD, Grafana,
   k9s) into `site/public/demo/shots/`:

   ```bash
   uv run --with playwright python3 scripts/journey/shots.py <system>   # needs Chrome, tmux and k9s (--k9s PATH)
   ```

   `journey measure` prints the wall-clock split (a person / waiting / agents), the tokens, the questions asked and the GitHub numbers used in the tables above, and per actor (coordinator, its subagents, repo sessions, their subagents) the sessions, calls, the median context of a session's first call (what each later call reads again) and the estimated cost from `scripts/cplat/prices.json` (one-hour cache writes at twice the input price); with `--steps` (one line `<ISO time UTC>\t<label>` per step start, written by the driver) also a per-step table: the split, tokens, calls and merged PRs per step, with agents as coordinator plus children (the system ship's repo sessions and their subagents), waits by kind (CI, deploy, promotion, restore, cluster, smoke), `unattributed` for waiting no evidence explains, and `no-tr` for minutes with no readable transcript. The waits by kind in the tables above come from it; `--journey` also writes the split to the journey record, and `scripts/journey/measure.py` still works (it forwards). A journey with a fresh session per part names each session, comma-separated. Take the per-part times from `cplat platform runs journey show`, count criteria in the demo repos' specs, and file every defect as an issue.
4. **Publish:** check the new screenshots (no secrets, no empty panels; captions in Watch a real run still true), cut the cast with `scripts/journey/cut_cast.py <cast> <markers> <inputs> <out> <host> 0.016 2.5 2.0` (waits capped, host name blanked; check the output for tokens), update Watch a real run, and add a row to each table here plus a paragraph under [What changed between the journeys](#what-changed-between-the-journeys) with the PRs and issues of the versions in between. When the journey is shown on Watch a real run, update the four numbers under "Measured, not promised" on the docs homepage (`site/src/content/docs/index.mdx`) from its rows, and keep the comparison with journey 3.
