**`pr wait` no longer sleeps on a GitHub rate limit while it holds the repo merge lock (#1028).** The lock is let go for the wait and taken again after it, so queued lands go on; the merge's head and base checks run after the lock is back. A long wait also looks at `gh api rate_limit` (REST) every 15 minutes and ends when the bucket has refilled, not only at the reported reset time.
