**Private GitHub Packages dependencies install in the image builds of `web-nextjs` and `service-typescript` (#965).** The image build could not read a private `@<owner>` package, so a repo that depended on one failed in Docker while `devbox run install` worked. The Dockerfiles now use frontend `dockerfile:1.10` and mount `PACKAGES_READ_TOKEN` as a BuildKit secret (`NODE_AUTH_TOKEN`) for the strict install, so the token is in no layer, build argument or history; CI passes it to the install steps and the image build, and the build works unchanged without it. `/platform:doctor` reports a missing `PACKAGES_READ_TOKEN` when `.npmrc` or `pyproject.toml` reads private packages. Update with `/shared:update-service`, then `gh secret set PACKAGES_READ_TOKEN` ([spec 104](../specs/104-generated-repos-build-and-observe/spec.md)).
