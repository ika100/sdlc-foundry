**Container logs now reach the log backend (#182).** Until now logs arrived only if a service's SDK pushed them. With `observability` on, the environment's collector pod runs a `log-tailer` container that follows every pod's stdout through the Kubernetes API (a namespaced Role for pods and pod logs; no ClusterRole, DaemonSet or host path, so the Kyverno guard rails still admit every workload) and sends it to the collector with `service_name`, `k8s_namespace_name`, `k8s_pod_name` and `deployment_environment`. The component templates log `trace_id` and `span_id` so a log line links to its trace. See [ADR-098](../adr/098-pod-logs-are-read-through-the-kubernetes-api-next-to-the-collector.md). Run `/platform:update` to pick it up in existing environments.
