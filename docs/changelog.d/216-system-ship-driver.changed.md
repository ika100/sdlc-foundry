**A system ship's mechanical steps run in a detached `cplat` driver, not in the coordinator's session (spec 216).** In journey 23 the step "One spec for the whole system" took 24.4 M tokens and 51 minutes, and the coordinator alone used 8.0 M tokens in 78 calls, 31 of which only relayed what `cplat system ship` had decided (`next --json`, `repo start`, `next --wait`, `complete`, `finish`). Now `/system:ship` runs `cplat system ship phase publish`, then `cplat system ship drive`: a detached process that starts no model publishes, starts the repo sessions, lands, completes and finishes. The session runs `cplat system ship wait` and acts on its result (`WAIT:`, `TIMEOUT:`, `ENTRY:`, `ENDED:`, `DONE:`, `ESCALATED:`, `STOPPED:`): it builds the gitops entry and hands over. `CPLAT_SYSTEM_DRIVER=0` brings back the loop in the session (`references/ship-loop.md`), which is also the path for a person who answers a held repo's questions. The measure of AC-216.12 runs on the first journey after the release (`cplat platform runs journey measure`): at most 40 coordinator calls and 4.0 M tokens in "One spec for the whole system", else the default flips to off ([ADR-129](../adr/129-a-system-ships-mechanical-loop-runs-in-cplat.md)).
