**A .NET service shape: `/component:new <name> <description> --lang csharp` (#719).** A team on .NET could not build its backend on the platform. The new `service-dotnet` shape creates an ASP.NET Core minimal API service on the pinned .NET 10 LTS with the same guarantees as the other services: the canonical `devbox` recipes and gates (`dotnet format` + the .NET analyzers with warnings as errors, xUnit with an 80 % line coverage gate, trivy over the NuGet lock files + detect-secrets), `/health` and `/ready` as ASP.NET Core health checks, `/metrics` (prometheus-net, HTTP request metrics by route), JSON log lines that carry the trace ids, OpenTelemetry tracing when `OTEL_EXPORTER_OTLP_ENDPOINT` is set, smoke tests of category `smoke` (and `writes`), a chiseled non-root image and the hardened CI with `release-image` and `pin-dev`. `--data needs_database=true` adds PostgreSQL through EF Core and Npgsql: migrations from `devbox run migrate-new` applied at startup, the `PG*` variables of the postgres resource, readiness that follows the database, Testcontainers tests. Its agents are in the new `svc-dotnet` plugin; a system's `system.yaml` accepts `type: service, lang: csharp`; `gate.sh` counts `dotnet test` results from its TRX report. Update the plugins (`/plugin marketplace update`) to get `svc-dotnet` ([ADR-127](../adr/127-service-dotnet-stack.md), [spec 218](../specs/218-a-net-service-shape/spec.md)).
