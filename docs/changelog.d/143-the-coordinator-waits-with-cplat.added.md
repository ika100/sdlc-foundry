**The coordinator waits with `cplat`, not with hand-written polling loops (#475).** Commands that left the coordinator to wait made it write its own loops on `kubectl get applications`, a deployment's image, `cplat component ship status` or `gh`: slow fixed sleeps, a new loop after every tool limit, `Synced Healthy` on the old revision counted as done, and no word when Argo CD had not picked up a merge yet. Now the waits are `cplat` commands with one contract (exit 0 reached, 1 red or escalated, 2 timeout, a line per change, 540 s default): `cplat system wait --env <env> [<component>…]` waits until every Argo CD app of the environment is synced to the head of the gitops repo's `main`, `Synced`/`Healthy` and running the pinned image, stops at once on a sync error, a failed sync or `Degraded`, and on a timeout names what each app waits for and prints the command with `--refresh` (a hard refresh) when Argo CD is behind; `cplat cluster wait` does the same for the cluster repo's roots; `cplat component ship wait --repo <clone> [--phase P]` waits for a ship run in another clone; `cplat system ship next --wait` blocks while a system ship's action is `wait`; `cplat component release wait --commit <sha>` replaces the release's shell loop on `main`'s `ci` run. A wait asks GitHub at most once and counts toward the run it runs in. `/component:set`, `/component:add` (an exposure now merges as in `/component:set`), `/instance:promote`, `/system:set`, `/resource:add`, `/cluster:add`, `/system:ship` and `/component:release` name the wait to run, pass `--refresh` after their own merge, rerun a timed-out wait at most twice and then escalate with cause `environment`; a test fails on a `sleep` loop on `kubectl`, `gh` or `cplat` in any command or agent file ([spec 143](../specs/143-the-coordinator-waits-with-cplat/spec.md), [ADR-082](../adr/082-a-coordinator-waits-with-a-cplat-wait-never-a-polling-loop.md)).
