**After a release, `/platform:next` recommends the prod database's backup before the prod promotion (#861).** The prod promotion was the recommended choice even when the prod database had no backup, so the prod PR opened before the backup the person wanted first, and a restore drill had nothing to restore. When an in-cluster prod database has no backup, the Prod question now says so and recommends "Set the backup first" (`/resource:backup <db> --env prod --to <bucket> --schedule daily`, the bucket another environment backs up to, else `<db>-backups`, declared in the same PR); "Promote to Prod" stays the second choice. This holds for the system's promote items and for the deploy step of a component repo.
