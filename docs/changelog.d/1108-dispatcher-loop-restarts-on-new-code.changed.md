**The dispatcher loop restarts itself when its platform checkout moves (#1108).** `cplat dispatch start` kept the code it started with while its units already ran the newer checkout, so merged fixes to the loop needed a manual restart and a lazily imported module could come from the newer code. After a cycle with no unit running, the loop now compares the checkout's commit with the one it started at and, when it moved, releases the lock and re-executes itself (same pid, same log); its state is on disk and nothing is lost.
