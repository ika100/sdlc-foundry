**`plan-check` refuses a web consumer decision that its contract test cannot pass (#985).** A system plan could tell the web repo to show "its own fixed messages, never the API's detail text", while the generated contract test (`lib/contract/engine.ts`, AC-110.7) feeds each rule's error body and expects the provider's `errors.body.message` at the field, so the web repo was held until the spec was amended (about 75 min in journey 26). Now `devbox run plan-check` in the gitops-app repo fails an active plan when a `web-nextjs` consumer of a rule has such a decision in the spec's assumptions, the `## Contract` text, its plan section, `arguments` or criteria. The error names the assumption or text, the rules, the contract test and the fix: show the provider's message at the field (the board may still check before sending), or change the contract. Unlisted answers, an "except" and the "(other option: …)" part are not read as such a decision. Repos pick the check up with `/platform:update`.
