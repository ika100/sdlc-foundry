**Parallel-safe plan tasks run in parallel again when worktrees start at `main` (#501).** A session started outside the repo root (as `/system:ship` does) never reads `worktree.baseRef: "head"`, so the worktree probe of `/component:build` saw `main`'s HEAD and every task ran one after another. A probe off the feature head no longer means sequential: each coder of a parallel batch first resets its worktree to the feature head, and `cplat component build merge` refuses a task branch that does not contain the acceptance tests. Only a worktree that cannot be created makes the build sequential. Update the plugins (`/plugin marketplace update`).
