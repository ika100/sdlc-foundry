**The e2e scope counts only the pull request's own changes (#814).** On a `synchronize` event the event's base sha can lag behind main, so `scripts/e2e-scope.py` compared the merge commit with an old main and counted main's newer changes as the pull request's: a spec-only PR started the full cluster e2e. On a merge commit it now compares against the first parent (the base branch as merged).
