**`/issue:triage` now proposes a priority `P0`, `P1` or `P2` with a reason, and you confirm or change it (#196).** Triage used to leave the priority of an issue and of the spec made from it to chance. Now each issue gets a proposal by the issue definitions (P0: an outage, data loss, a security problem, or something that blocks all other work; P1: a normal bug or feature, the fallback when nothing signals urgency; P2: cosmetic, a convenience, or something with an easy workaround), a label already on the issue is kept, and nothing is labelled until you confirm or change it (`560 p0`). A confirmed feature that becomes a new spec gets the confirmed priority and the issue the matching label; the finish block of a new spec shows `Priority:`, and `priority P0` changes it. In an unattended run the priority is only proposed: the spec stays draft and nothing is labelled. The dispatcher's default rules now start with `label:p0`.
