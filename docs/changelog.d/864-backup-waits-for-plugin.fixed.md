**The first database backup no longer turns the environment Degraded while the backup plugin it installs is still starting (#864).** The first `cplat resource backup` pull request installs the Barman Cloud plugin through the operators application and sets the database's WAL archiving through it in one change. Argo CD applied the database before the plugin ran, so CloudNativePG restarted the primary into "wal archive plugin is not available" and the environment stayed Degraded for minutes, while `/system:status` said "archiving failing". A backed-up database now waits for the plugin in a PreSync hook (`plugin-wait-job.yaml`, up to 10 minutes) before its cluster changes, when the system repo installs the operators. For the first 15 minutes a missing plugin shows as "archiving waiting for the backup plugin to start" (backup state `pending`), and an on-demand backup says the plugin is still starting; after that it is a failure as before.
