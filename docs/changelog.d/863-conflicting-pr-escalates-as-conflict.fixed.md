**A pull request that conflicts with main stops as a conflict, not as "check the runner" (#863).** GitHub creates no `pull_request` workflow run for a conflicting pull request, so `cplat pr wait` and the land ended with "no pull_request workflow run was created ... is a runner online?" and the dispatcher escalated spec 158 as an environment problem. When no such run appears, the wait now reads the pull request's mergeable state first: a conflicting one goes the conflict path (the land merges main in and regenerates generated files, or stops naming the conflicting files), and only a mergeable one still points at the runner and the trigger.
