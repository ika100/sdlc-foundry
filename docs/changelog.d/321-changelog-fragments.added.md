**Platform changelog entries are fragments, so parallel PRs no longer conflict in the changelog (#321).** Every platform PR added its entry at the top of `[Unreleased]` in `docs/CHANGELOG.md`, so parallel PRs conflicted there one after another and each needed a rebase and another CI round. A change now adds one file `docs/changelog.d/<id>-<slug>.<added|changed|fixed>.md`; `cplat platform release` assembles the fragments with any text still under `[Unreleased]` into the new version section (Added, Changed, Fixed) and deletes them in the release commit. `scripts/release-check.py rows` and the release preflight count fragments as unreleased content and reject a misnamed or empty one. The old changelog acceptance tests now find their release by its version heading instead of the first section that mentions their spec, and plugin version tests check `>=`, so a later entry or bump no longer breaks them. Contributors to this repo: write a fragment instead of editing `docs/CHANGELOG.md` (format in `docs/changelog.d/README.md`); text written under `[Unreleased]` keeps working.
