**`/issue:triage` asks reporters plainly and closes what needs no work (#177).** Triage named internal terms and asked for fields the issue form already holds, and confirmed question, duplicate and wontfix issues stayed open for ever. Now the batch names the missing form fields, plain reporter comments are checked (thanks, each missing item in plain words, no spec numbers or labels, a days-and-reopen sentence), and `cplat issue triage act` closes the confirmed question, duplicate, wontfix and silent `needs-info` rows as not planned, only when a person names them in `--rows`; an unattended run closes nothing. A closed `needs-info` issue its reporter answers is requeued and reopened. The days of silence come from `needs_info_close_days` in `.platform-settings.yml` (default 14). The hard rule `triage-never-closes` now reads "never close an issue without the user's confirmation" ([ADR-129](../adr/129-triage-closes-confirmed-issues.md), [spec](../specs/177-triage-asks-reporters-plainly-and-closes/spec.md)).
