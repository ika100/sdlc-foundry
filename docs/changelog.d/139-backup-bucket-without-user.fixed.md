**A backup bucket no longer has to be used by a component (#418).** `backup: {to: <bucket>}` on an environment or a database instance failed render unless a component running there listed the bucket in `uses` ("a component that runs in prod must use it"), so that component received the bucket's S3_*/AWS_* credentials and could delete its own backups. Now a bucket that is a backup target gets its instance in that environment without a using component, with its credentials only for the database's ObjectStore and Velero; an external target's ExternalSecret goes to `addons/<env>/<bucket>/` when no component uses it. Systems that keep the `uses` render byte-identically. A database instance still exists in an environment only once a component that uses it runs there ([spec 139](../specs/139-a-backup-bucket-without-a-using-component/spec.md)). **Action:** none required. Optionally remove the backup bucket from `components.<name>.uses` in `system.yaml` where a component listed it only to make render pass, then `devbox run render`: the component loses the bucket's variables, and an external bucket's ExternalSecret moves from its overlay to the addon directory (its Secret is kept).
