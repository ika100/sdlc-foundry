**`/platform:next` now builds, answers stops and releases by choosing, and `cplat dispatch` has the verbs behind it (spec 193).** Where the run queue stopped at a decision or waited to be started, the person had to type `cplat dispatch` commands. Now `/platform:next` shows the queue in the order it will build, sets up the policy through a pull request that merges on green CI when none exists, starts the build detached (`cplat dispatch build --slots N`, `cplat dispatch start --detach`), shows its progress (`cplat next --watch`) and, at a stop, offers the suggested answer and one alternative; the answer is written into the spec as an assumption the person decided (`cplat dispatch answer <item> --answer TEXT`), or comments on the issue of a fix. At the end of a build it offers release, and for a deployable repo promotion to staging and prod in that order. A raise of the day's token budget (`cplat dispatch budget --today N`, undone with `--reset-today`) holds for the local day in the dispatcher state and never changes the policy file ([ADR-119](../adr/119-a-days-budget-raise-lives-in-local-state.md), [spec 193](../specs/193-building-and-releasing-run-on-their-own/spec.md)). `cplat dispatch resume <item>` now also lifts the `needs-decision` label of its issues. Update the plugins (`/plugin marketplace update`).
