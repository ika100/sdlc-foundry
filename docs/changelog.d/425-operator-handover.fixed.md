**A local cluster no longer runs External Secrets or Kyverno twice once the gitops repo installs them from `operators/` (#425).** A cluster made by an older `cluster-up` had both as k3s HelmCharts (`kube-system`); when the repo later rendered `operators/apps/external-secrets.yaml` or `kyverno.yaml`, `cluster-up` "kept" the HelmChart but still applied `operators/root.yaml`, and `bootstrap` (also run by the ship flow after a merged `operators/` change) applied it without looking, so Argo CD and the k3s Helm controller both managed the same release and CRDs. The new `scripts/operator-handover.sh`, run by `cluster-up` and `bootstrap` before they apply `operators/root.yaml`, hands each such HelmChart over to Argo CD: it marks the release's CRDs `helm.sh/resource-policy: keep`, marks the HelmChart unmanaged and removes its `wrangler.cattle.io/on-helm-chart-remove` finalizer (so deleting it runs no `helm uninstall`), deletes the HelmChart, its install job and the Helm release secrets, applies `operators/root.yaml`, and fails naming any CRD, ExternalSecret, secret store or policy count that changed. Fresh clusters and operators the repo does not render are left as they are. **Action:** `/platform:update` in each gitops repo, then `devbox run cluster-up` (or `bootstrap`) once on a cluster that still has the HelmCharts.
