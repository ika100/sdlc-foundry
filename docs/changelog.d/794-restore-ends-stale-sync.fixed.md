**A discard or restore ends an Argo CD sync that still waits for an earlier copy (#794).** After a restore whose copy never became healthy, Argo CD's sync of the database's application kept waiting for that copy, so the discard and later restores merged but were never applied, and the copy stayed in the cluster. Before it asks Argo CD to refresh, `cplat resource restore` now ends a sync still running for an earlier revision and says so.
