**Smoke tests that write data run only in dev; staging and prod run read-only smoke checks (#474).** The components' smoke tests ran in dev, staging and prod (after deploys and on `/instance:verify`) and left what they created behind, so prod filled up with `smoke-…` tasks. cplat now passes `SMOKE_ENV=<env>` to `devbox run smoke` and, outside dev, `SMOKE_READ_ONLY=1`; the templates' smoke harness then leaves out every smoke test marked as writing: `@pytest.mark.writes` (service-python), `@Tag("writes")` (service-java), the name `TestSmokeWrites<Name>` (service-go), `@writes` in the title (web-nextjs). The rule is in each template's CLAUDE.md (Smoke tests) and in the tester agents. Outside dev, a run in which no smoke test passed (every test writes, or there is none) is reported as `not run: no read-only smoke test ran in <env>` (exit 3 for `/instance:verify`, a WARNING in the prod evidence), never as passed, and `instance verify` records it. There is no cleanup: smoke data already in staging or prod stays until you remove it. **Action:** run `/platform:update` (it refreshes `scripts/smoke.sh`, the harness helper and CLAUDE.md), then mark your own smoke tests that create, change or delete data with the mark above, since `tests/`, `src/test/`, `internal/` and `e2e/` are yours and are not changed; keep or add at least one read-only smoke check so staging and prod still verify something. Update the plugins (`/plugin marketplace update`).
