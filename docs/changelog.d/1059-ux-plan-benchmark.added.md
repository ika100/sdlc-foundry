**The UX step is measured on a website plan, and it is chosen more precisely (#1059, #1060).** `cplat platform runs benchmark ux-plan --plugins plugins --dir <system-ship folder>` plans a fixed website spec (a status page) on system-ship's trusted `bench-files-web` clone, so the ux-designer runs. The run counts as done only when the plan wrote a current `ux.md` that passes `cplat spec check` and that the architect's design names. The eval gate, and so the platform release, asks for this benchmark only when a prompt under `plugins/web/` or `scripts/cplat/spec_ux.py` changed; every other release runs `quick-task` and `build` as before. `cplat spec ux` now also recognises inputs, rows, labels, headings, edit mode, keyboard focus, empty and loading states, screen readers, and a person typing, pressing, opening or saving. Server and build wording no longer counts as visible: a container image, JSON fields, a page size, a response header, what the logs show. On 41 labelled criteria from the journey and demo website specs, misses go from 15 to 0 and false hits from 7 to 0; a spec's `ux:` field still decides first ([spec 222](../specs/222-the-ux-step-is-measured-on-website-plans/spec.md)).
