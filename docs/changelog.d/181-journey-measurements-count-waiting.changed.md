**The journey measurement counts the system ship's repo sessions as agent time and attributes waiting only from evidence (spec 181).** The old `scripts/journey/measure.py` counted a minute as waiting whenever the coordinator waited, even while a headless repo session worked, and named the kind of wait from the command text alone. The measurement is now `cplat platform runs journey measure` (`scripts/journey/measure.py` forwards to it): each minute counts once, a person first, then agents when any thread works (the coordinator, its subagents, and the repo sessions found through the run records), then waiting. Waiting is attributed to CI, deploy, promotion, restore, cluster or smoke only from evidence (Actions runs, run-store phases, wait records), otherwise it is `unattributed`. `--steps` prints a per-step table, `--json` the exact split, and `--journey <run_id>` writes it to the journey record as a `journey_split` follow-up that `cplat platform runs report --benchmarks` shows as medians per stage, part and journey. See [ADR-096](../adr/096-journey-waiting-is-attributed-from-evidence.md) and [spec 181](../specs/181-journey-measurements-count-waiting/spec.md).
