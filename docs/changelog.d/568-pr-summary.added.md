**Every PR that `cplat` opens now starts with a four-line summary block (#568).** The block names what changed, why, what to review, and the risks and follow-ups, so a reviewer reads the point of the PR before the diff. `cplat` renders it purely from records (the spec, the plan, the run record and the verification), with no agent text, so it cannot drift from what happened. It sits at the top of the body for `cplat pr open`, for `cplat component ship pr` and for the gitops PRs of `cplat system ship`; the orchestrator writes none, and `/component:build`, `/component:ship` and `/system:ship` say so ([spec 157](../specs/157-prs-and-issues-get-short-summaries-for/spec.md)).
