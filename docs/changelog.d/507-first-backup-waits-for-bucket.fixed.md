**A new database backup waits for its bucket, and `/system:status` says when the last base backup fails (#507).** The `ScheduledBackup` of a database backed up to an in-cluster bucket was created together with the database, so its immediate base backup ran before the bucket's SeaweedFS answered and failed; CloudNativePG never retries it, so prod had no working backup until the next schedule, and the status showed the failure as a plain `last base backup never  archiving ok` line. The database's addon now carries a `bucket-wait-job.yaml`: an Argo CD Sync hook (wave 1, the credentials Job's pinned Python image) that waits until the bucket answers a signed `HeadBucket` with the ObjectStore's endpoint and credentials (at most 10 minutes, then it goes on), and the `ScheduledBackup` follows in wave 2. An external backup target is unchanged. The status line of a database whose last base backup failed, or is overdue, while archiving works now ends in `backup failing (<reason>)`. Existing gitops repos get the wait with `/platform:update` and a re-render.
