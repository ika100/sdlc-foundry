**One cluster repo can place a system's environments on several clusters (spec 201).** `cluster.yaml` gains `clusters: [local, home]` with `clusters/<name>/cluster.yaml` for each cluster's exceptions, and a system's environments run on the cluster that `systems.<s>.environments` (cluster repo) and `environments.<env>.cluster` (`system.yaml`) assign them to. `devbox run render` writes one tree per cluster and prints every exception, every cluster that is behind and every environment that moved; `/cluster:promote <name>` pins a later cluster to the release of the one before it after its operators and smoke tests pass; `/platform:doctor` compares the clusters. Not breaking: a cluster repo without `clusters` and a system repo without `cluster` keys render as before. The cluster plugin is now 1.5.0 ([ADR-114](../adr/114-one-cluster-repo-places-environments-on-several-clusters.md)). **Action:** update the plugins (`/plugin marketplace update sdlc-foundry`); to use several clusters, follow "Several clusters" in [docs/CLUSTERS.md](../CLUSTERS.md).
