**A quickstart that works as written, and docs that CI checks against the code (#587).** The README quickstart and the user journey installed only `shared`, whose commands moved to `system`, `component` and `platform` in 5.0, and the site's getting-started page left out `shared`, which carries `cplat`. There is now one quickstart, `docs/QUICKSTART.md` (the first page of "Get started" on the site): the starter plugins, the full sample manifest, and per step how long it takes, what you will see and what to do when it fails. A test runs its manifest through `cplat system new`. The new `scripts/check-docs.py` runs in CI and `devbox run quality` and fails when a user-facing page names a command that does not exist or is a tombstone, a flag its command file does not name, a tombstone-only plugin, an install block without the starter set, an undefined `devbox run` recipe or an invalid system manifest ([ADR-087](../adr/087-user-docs-are-checked-against-the-code.md)). Its first run found 80 problems, now fixed: among them `--secret-ref` of `/component:add`, which the command never documented, and 4.x bootstrap commands in the web, Java and Go plugin READMEs. The README is down to 94 lines (the maintainer notes moved to CONTRIBUTING), the GitOps repository is named `<system>-gitops` throughout the user journey, the 4.x tables moved from the domain model into the migration guide, and the v4 field reports and design-history pages left the site. Plugins: component 1.15.1, api 1.2.1, web 0.7.1, svc-go 0.7.1, svc-java 0.7.1.
