A system ship's repo sessions apply the repo's permission rules in a fresh clone. Claude Code ignores `.claude/settings.json` in a folder it has not trusted, and each repo of a system ship runs in its own new clone (spec 155), so every cplat command was refused and the ship escalated. `cplat headless` now passes the permission rules of the repo's committed settings (the HEAD version, so an uncommitted edit grants nothing) to each session as `--settings`. The file's hooks and other settings stay gated by trust, and `~/.claude.json` is not changed. Found by journey 7.
