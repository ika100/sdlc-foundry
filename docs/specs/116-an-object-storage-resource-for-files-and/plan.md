# Plan — 116 An object storage resource for files and backups

The contract (schema, messages, rendered documents, pins, CLI texts, doctor rows) is in [design.md](design.md). The decision
that outlives this spec is [ADR-059](../../adr/059-in-cluster-buckets-on-seaweedfs-per-instance.md). It builds on spec 115's design
and ADR-057/058. Levels: t1, t4, t5, t7, t8, t10, t11, t12 → t2 → t3 → t6, t9.

`render.py` changes in three sequential tasks (t1 → t2 → t3). Every other task owns its files. Never edit
`scripts/cplat/assets/render_v4.py`. Every 5.0/115 `system.yaml` must render byte-identically. The 115 suites, amended only by
t12, prove that.

## t1 — render.py: bucket schema and validation

**Files:** templates/gitops-app/scripts/render.py
**Covers:** AC-116.1, AC-116.2, AC-116.10, AC-116.20
**Goal:** `type: bucket` is accepted with its keys and refused in every invalid form with the texts of design.md (Render errors).
Nothing is rendered for it yet.

**Implementation notes:**
- `PLANNED_TYPES = {"cache": 118, "broker": 119}`. Add `BUCKET_KEYS`, `BUCKET_INSTANCE_KEYS`, `BUCKET_SIZING_KEYS = ["storage", "versioning"]`,
  `BUCKET_SUFFIXES`, `STORAGE_SIZE` and `S3_BUCKET_NAME = re.compile(r"^[a-z0-9][a-z0-9-]{1,61}[a-z0-9]$")`. The database constants
  keep their names and values.
- In `validate_resource`, select the key, instance-key and sizing lists by type, and keep 115's check order. The external-sizing
  texts for a bucket are AC-116.10's. A database's texts do not change.
- `versioning` must be a bool and `storage` a size string, at the resource level and per instance. Then, only where some environment
  is in-cluster, check the S3 name and the 45-character rule on `<system>-<name>`. Skip the database `version` check for buckets.
- The normalised envs of a bucket are as in design.md (Renderer API), with defaults `"10Gi"` and `False`.
- `object_names`: a bucket uses `BUCKET_SUFFIXES`. `cache` and `broker` keep `-app`.
- Update the module docstring's `resources:` block with a bucket example.
- Rendering may still fail for a used bucket until t2. Tests of this task use validation only.

**Done when:** the AC-116.1, AC-116.10 and AC-116.2 name-rule tests pass, as do the render half of AC-116.20 (`cache`/`broker`
texts unchanged), and the 115 render suites stay green after t12.

## t9 — e2e: buckets in the cluster

**Files:** tests/e2e/run.sh
**Covers:** AC-116.5, AC-116.6, AC-116.7, AC-116.8, AC-116.14, AC-116.18, AC-116.19
**Goal:** the end-to-end test proves the bucket contract in a real cluster, and fails naming the step (endpoint unreachable, access
denied, content differs).

**Implementation notes:**
- Before cluster-up: `cplat resource add files --type bucket`, then `instances.dev.versioning: true` in system.yaml. Start the
  cluster with `WITH_SEAWEEDFS=1`, as is done for CloudNativePG.
- e2e-api and e2e-web both use `files` in dev (e2e-web already uses `ext-db`: different types, no prefix). Assert that
  `operators/apps/seaweedfs.yaml` exists and that the installed chart equals its `targetRevision`.
- Apply the dev bucket addon in the sync-wave order (generators and ExternalSecret, wait for the Secret, then the rest). Wait for
  the bucket to be ready.
- Probe "through the component's variables": a one-off pod with a pinned AWS CLI image whose `env` is copied from the rendered
  e2e-api container (`valueFrom` entries). Path style comes from `S3_FORCE_PATH_STYLE`. It puts an object and reads back the same
  bytes (AC-116.14). A second probe with e2e-web's variables lists, reads and deletes it (AC-116.6).
- Versioning (dev, `Enabled`): overwrite, then fetch the old version by its id (AC-116.7). Restart: delete the store's pods, wait,
  and read again (AC-116.8).
- After the staging promotion: apply the staging bucket addon (`versioning` false). Overwriting keeps only the latest version
  (AC-116.7), and dev's keys are refused by staging's endpoint (AC-116.5).
- External: `resources.ext-files: {type: bucket, external: true}` used by e2e-web, with a store entry `e2e-dev-ext-files` that lacks
  `secretAccessKey`. Check: no Secret, the ExternalSecret names the key, the pod is not Ready. Complete the entry, and the Secret then has the six keys (AC-116.18).

**Done when:** `tests/e2e/run.sh` passes on a local machine with the release candidate. Record the run in the verification.
