- `create.py` steps 1–5, log lines, exit codes 1 and 2, `CREDENTIALS_API_URL`/`CREDENTIALS_SA_DIR`, retry on 403/429/5xx (`R:2300-2684`).

- The migration proof.
- The e2e harness (credentials files first, `wait --for=condition=complete … --timeout=180s`, logs on failure).

One small addition to the contract: `verify_servers` logs `skipped <pod>: could not check every password` when a probe answers "unknown" and none refuses. The design leaves this case open. It never restarts a pod, so it is consistent with "Unknown never restarts".

## Ship gate (must hold before merge)

1. `e2e.yml` (`run.sh`) and `e2e-upgrade.yml` (`upgrade.sh`, v5.4.x → candidate) are each green in 3 runs in a row on the PR head (AC-128.11; plan t5/t6 Done-when). Until then, the runtime evidence for AC-128.1–.8 and .10 comes from the fake-API tests only.
2. Flakiness risk to watch in `upgrade.sh`: `force_password` patches a Secret that a 5.4 `CreatedOnce` ExternalSecret still owns. By ADR-072's own finding, a data-hash mismatch makes ESO refresh and regenerate the Secret. ESO may therefore rewrite the Secret between `record_hashes` and the Job retiring the ExternalSecret. That would make `check_kept` (AC-128.9) fail spuriously in staging or prod. If a run fails there, look at this window first, before suspecting the renderer.
3. Human step (plan): one real `/platform:update` under Argo CD, to confirm the PreSync hook syncs and keeps the Secrets. No CI run exercises Argo CD hooks.
