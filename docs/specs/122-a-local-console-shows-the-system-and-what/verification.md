## Root causes for the coder

1. **The run list does not fill the run-row contract from real records** (`runlist.py:162-179`). `pr`, `ci_url` and `image` are read from keys no command writes. `smoke` is passed through in the record's shape `{env, outcome, …}` instead of `{result, instance}`. `staging` is never derived. Done runs get `stage: None`. This affects AC-122.5, .14, .15, .33, .39, .48 and .49. Derive these from the record: the `smoke` and `smoke.staging` sections and `promotion.staging`, the PR from the ship or pr-wait sections or `gh pr list --head`, the image from `smoke.image`, and the stage reached of a done run from its last phase.
2. **No source lists open issues.** Only `triage` items reach the console, which affects AC-122.10, .19, .48 and .49. Add open issues without `tracked` (and closed ones for Done) to `needs` or to a new source.

4. **Some one-click actions skip the consequence**: Promote on a System cell (AC-122.8) and Cut release on a cell or card (AC-122.47). Open the Inbox or release panel, or show the consequence before confirming.
5. **`status` resource cells have no `state`** (`status.py:216-218`), which affects AC-122.7.
6. Smaller issues: `needs` promote `since` (AC-122.4); the spec panel shows raw status (AC-122.32, `panels.py:227`); per-slice activity (AC-122.13); new-system form checks (AC-122.20); ask suggestions without a diff (AC-122.21); "Open" in the switcher (AC-122.29); the cwd of a new session (AC-122.36).
