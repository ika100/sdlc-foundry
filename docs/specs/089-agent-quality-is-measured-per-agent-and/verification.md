## The changed acceptance tests (commit a36089a)

After the red commit de6a3b9, commit a36089a changed two acceptance tests. `cplat spec test-diff de6a3b9` reports both files (exit 1). `cplat spec test-diff a36089a` prints `no acceptance test changed` (exit 0). I re-ran both with `CPLAT_PLATFORM` set to the worktree. No other test file changed after de6a3b9 (`git diff --stat de6a3b9..HEAD -- tests/`: 2 files, +3/−1). I agree with the driver that both are harness bugs and that the criterion's meaning is unchanged:

1. **`test_runs_report_agents.py::test_since_widens_and_narrows_the_window`** (AC-089.11). The red version asserted that a 1-day window has no rows. `NOW` is `2026-10-24T08:00Z` (`test_runs_report.py:12`), so the cutoff is `2026-10-23T08:00Z`. The fixture's architect records `a3` (`2026-10-23T12:00Z`) and `a4` (`2026-10-24T12:00Z`) lie after the cutoff. `select` (`runs_report.py:63-80`) is the 087 window: it has a lower bound only, and 087 already tests it. So an empty result was impossible for any correct implementation. The new assertion (only `svc:architect` with 2 runs) still proves that `--since 1` narrows the window: the coder row, with 2 runs at 30 days and 3 at 90, disappears. The test is now stricter, not weaker.
2. **`test_runs_agents.py::go_test_repo`** (AC-089.7). The fixture spec 007 was `approved`. `spec.test_diff` only guards test files that name a criterion of a `building` spec (`spec.py:426-437`). That rule is unchanged from origin/main, where it is spec 063 behaviour. So with an approved fixture, test-diff found no file, and the refusal tests could never fail as intended. During a real build the spec is `building` (build.md Phase 0), so setting the fixture to `building` matches the situation the criterion describes. The assertions themselves are unchanged: exit 1, the file, the task and the charged agent.
