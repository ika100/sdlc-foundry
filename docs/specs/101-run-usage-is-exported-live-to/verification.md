## Risks (not verdicts, but should be checked before release)

- **The `cplat_run_id` label.** Cycle 2 sets `OTEL_METRICS_INCLUDE_RESOURCE_ATTRIBUTES=true` (`telemetry.py:202`, tested by `test_each_identity_switch_is_false`). Per the coordinator, Claude Code's docs say this switch copies the resource keys onto every datapoint, so Prometheus' OTLP receiver sees `cplat_run_id` as a series label and not only on `target_info`. `design.md:10` says the pairs land "on every datapoint and event", but it does not name this switch as the mechanism, and I could not check Claude Code's docs from here. The tests fake the store. One end-to-end check on a kind cluster (Grafana Explore: `claude_code_token_usage_tokens_total` carries `cplat_run_id`) would close it.
- `compare` reads `query_url` and the context from `Path.cwd()` (`telemetry.py:301`, `:305`), not the run's repo. That only matters for the project settings file when cplat runs from another directory.
