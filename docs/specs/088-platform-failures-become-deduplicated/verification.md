## Contract

The design.md public API of `autoissue.py` is all there with the documented signatures: `KINDS`, `KIND_LABELS`, `BASE_LABELS`, `SIGNATURE_LINE`, `DEFAULT_BRANCHES`, `SUBCOMMAND_GROUPS`, `CAP`, `WINDOW_S`, `TIMEOUT_S`, `RESULTS`, `EXTRA_LABELS`, `now`, `monotonic`, `default_repo`, `enabled`, `Draft` (`to_payload` / `from_payload`), `Issue`, `Outcome`, `TrackerError`, `Tracker`, `gh`, `GhTracker`, `tracker`, `render`, `render_comment`, `file`, `retry_filing`, `crash_draft`, `file_crash`, `normalise`, `raw_signature`, `signature`, `private_names`, `scrub`. Specs 091 and 092 can import it as ADR-033 describes. Output lines, body layout, comment layout and the ledger location match. The coder's deviations:

1. **`scrub()` protects runs of 40 or more of one repeated character** from `feedback.redact`'s `<long-string>` (ai:149-162, swapped out via private-use sentinels and restored after redaction). The red test `test_evidence_is_cut_to_80_lines_and_6000_characters` needs this, because it expects `"B" * 9000` to survive. Acceptable, with one residual risk: a token-shaped string built from such a run is no longer redacted (probe: `"token ghp_" + "A"*40` and `"abcDEF123" + "0"*40 + "xyz"` survive). Real GitHub tokens are random and end in a checksum, so they are not single-character runs. The AC-088.9 cases stay redacted. Suggested hardening (not required): protect a run only when it is not glued to other word characters.
2. **For signatures only, the `<repo>` and `<branch>` placeholders become `<path>`, and the bare repo name (the part after `/`, 3 or more characters) is also replaced** (ai:99-108). This keeps "the same failure in two repos" equal whether a name came from `names` or from the path rule (step 6). Issue text still uses `<repo>`/`<branch>` (ai:163). Acceptable, and it follows AC-088.5's intent. Minor: the bare name is replaced without word boundaries, so a repo called `acme/api` also rewrites `api` inside other words in that repo's signature input. This only makes signatures from such a repo less stable. It never leaks anything.
3. **Compound durations collapse into one `<duration>`** (ai:81-82; `3m 20s` vs `45s`). AC-088.5 requires this ("durations"), and test case 1 asserts it. Acceptable.
4. **Same-run idempotency applies only on the retry path** (`record=False`, ai:561-563): a second live filing in the same run is a +1. Design said `file()` checks the run id for both. S::test_the_same_crash_again_is_a_plus_one (two crashes in one run, one comment expected) contradicts the design, and AC-088.7 ("filed again … one comment is added") supports the test. The retry contract still holds: `retry_filing` passes the run id (ai:577), so a retry after a lost response neither files nor comments twice (A::test_filing_the_same_run_twice_is_idempotent, A::test_a_retry_is_deduplicated_against_an_issue_filed_meanwhile). Acceptable.
5. **The `suppressed` note is only written when a filer is passed to `runs.filed`** (`runs.py:399-400`). `autoissue.file` always passes `filer="autoissue"`, so every 088 suppression gets the note. 087's own calls and tests (no filer) keep their exact entry shape. Acceptable.
6. **The message for an unrecognised cause says "missing" too:** `cause '<v>' is missing or not known: …` (`ship.py:248`), where design said `cause '<v>' is not known: …`. AC-088.3 says "the output says the cause is missing" for both cases, so this follows the spec literally. Acceptable.
7. Further minor point: `GhTracker.find` returns the open list alone when it has a match and skips the search (ai:309-310). Design said both lists are joined. `file()` only looks at closed issues when no open one matches, so the outcome is the same. Acceptable.
