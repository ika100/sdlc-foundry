## Deviations from the plan

- All tasks t1, t2 and t3 are `done: true`. Every changed file is in some task's `files`, apart from the spec folder's pipeline artefacts and the tests from the red commit. `update.py` is untouched, as t1 requires.
- **Hints folded into the message** (`scripts/cplat/fleet.py:83-84` for `--ref`, `:222` for the gh login). The design asks for `PlatformError(..., hint=...)`. The red-commit harness (`tests/cplat/fleet_world.py:219-221`) prints only `ERROR: {e}`, yet the tests assert `gh auth login` and `CPLAT_REF=...` in stderr, so the text has to be in the message. Through the real launcher the user sees one line, `ERROR: gh is not logged in; fix: gh auth login`, instead of the usual `ERROR:` plus an indented `fix:` line. The same information reaches the user. **Acceptable**, but cosmetically off-pattern. Setting `hint=` as well would print the fix twice, so leaving it as it is is reasonable.
- **Any exception after the PR exists → `failed` with the PR link kept** (`scripts/cplat/fleet_pr.py:227-230`). The design's table separates "a failing PR call → failed" (label/comment `PlatformError`s) from "a non-`PlatformError` after the PR exists → failed, keep link". The code handles both with one `except Exception`. `pr.wait`'s own `PlatformError`s are caught earlier inside `_wait` (:175-187) and become `left open`, as the contract requires. So the only `PlatformError`s that reach this handler are failing label/comment calls, which the design also maps to `failed: <step>: <line>`. Keeping the PR link is strictly more information. **Acceptable.**
- The `--ref` format error (`fleet.py:81`) has no hint. This is harmless.
- **Post-red harness fix 09c612d** (`tests/cplat/fleet_world.py` only; no assertion changed). `update._readme_changed` (`scripts/cplat/update.py:208-214`) diffs against the tag `v<old>` in the platform checkout. A shallow CI clone has no tags, so it returned True there and put a `README.md kept ...` step ahead of `new template answers took their defaults`. That broke `test_follow_ups_are_printed_under_the_repos_row`, which checks the first `next:` line. The harness now stubs `_readme_changed` to False, next to the existing `render_baseline` stub. This was a harness bug that depended on the environment. The fleet code is unaffected: `follow_ups` (`fleet_pr.py:82-83`) still relays a README step when there is one, and the stub changes no file content, so the AC-096.3 tree comparison is unaffected too. AC-096.14 still means the same and is still `met`.
