# Design — 114 The platform speaks the domain model (5.0)

## Decisions

- **`render.py` is the only validator of `system.yaml`** (AC-114.2–AC-114.20, AC-114.57, AC-114.58). It loads the file, checks it, and resolves it into per-instance entries that its 4.x manifest builders consume unchanged, so the 5.0 render of a converted system is the 4.x render by construction. `cplat`'s model (`model.py`) loads `system.yaml` leniently and never re-checks a schema rule. ADR: [054](../../adr/054-five-zero-interface-and-proved-migration.md).
- **The migration proves byte identity with a frozen 4.x renderer** (AC-114.40, AC-114.42, AC-114.68). The current `templates/gitops-app/scripts/render.py` is copied verbatim to `scripts/cplat/assets/render_v4.py` before it is changed. `cplat platform update --migrate` renders a temporary copy of the repo with it, converts, renders with the 5.0 renderer, and compares every generated file. One table-driven converter (`migrate5.py`) does the conversion; it is pure and runs in `--dry-run` too.
- **`cplat` dispatches `<noun> <verb>` to the existing command modules** (AC-114.60). Modules keep their logic; only their argument shapes change where the spec says so (`instance promote --to`, `instance secret set <component>/<env>`, `component new --type/--lang`). A 4.x top-level name exits 2 with one line (AC-114.26).
- **Seven noun plugins hold every working slash command; `svc`, `shared`, `app` and `gitops` hold tombstones** (AC-114.27, AC-114.59, AC-114.65, AC-114.66). Tombstones are generated by `scripts/tombstones.py` from one table. Commands that read files relative to `${CLAUDE_PLUGIN_ROOT}` move with those files (`plugins/svc/references/` → `plugins/component/references/`). Agents stay in `svc`, `svc-java`, `svc-go`, `web`, `shared`; the planner moves to `system`.
- **Noun commands take `--system NAME`** where 4.x took `--app NAME` (the application directory); the plumbing commands `model` and `alerts` keep `--app`. Internal names that are not user-facing stay: the `applications/` directory, `.platform-app.yml`, the state files `cplat-ship.json` / `cplat-app-ship.json`, the shape ids, the `app_name` copier answer.
- **The alert poll runs per environment** (AC-114.10): each environment with `observability` (and `alerts` not `false`) is one source with its own rules and endpoints; the system's issues are reconciled once over all sources, so issue signatures and the state file do not change.
- **Unmigrated detection is one rule everywhere** (AC-114.22, AC-114.23, AC-114.27, AC-114.44): a gitops-app application directory is unmigrated when it contains `app.yaml` or `services.yaml`; any repo is unmigrated when `.platform-version` is missing or its `platform:` major is below 5. The message is the constant `model.NOT_MIGRATED` = ``not migrated to 5.0: run `cplat platform update --migrate` ``.
- **Kept 4.x key: `metrics`.** AC-114.12 does not list it, but `compose` writes it and both the collector scrape and the `ServiceDown` rule read it; dropping it would change rendered bytes. It stays a component key with its 4.x meaning.
- **YAML 1.1 `off`.** PyYAML reads an unquoted `policy: off` as `false`; `render.py` and the model treat `false` as `off` (and `true` as an invalid value). The migration writes the quoted string.

## Contract — `system.yaml`

`applications/<system>/system.yaml` is the only hand-edited file of a system (AC-114.1). Versions are never in it (AC-114.20).

```yaml
system: todo                       # required; equals the directory name
owner: acme                        # required non-empty string (AC-114.57)
gateway: {name: traefik-gateway, namespace: kube-system}        # optional, as 4.x app.yaml
secretStore: {name: platform-secrets, kind: ClusterSecretStore}  # optional, as 4.x app.yaml
registries: [docker.io/library/]   # optional list, as 4.x policies.registries

environments:                      # required: exactly dev, staging, prod in this order
  dev:
    host: "{component}.{system}-dev.localhost"   # optional; no host = nothing exposed there
    url: "http://{host}:8088"                     # optional; read by smoke/ship/instance verify, ignored by render
    policy: audit                  # audit | enforce | off; default audit (dev, staging), enforce (prod)
    observability: {ui: lgtm, alerts: true, rules: [...]}   # optional; 4.x addon keys and checks
  staging:
    promote: after-dev-smoke       # staging: after-dev-smoke | manual (default)
  prod:
    promote: manual                # prod: only manual; dev: no promote

components:
  todo-api:
    type: service                  # required with lang (pairs below)
    lang: python
    repo: acme/todo-api
    image: ghcr.io/acme/todo-api   # no tag
    port: 8080
    probes: {liveness: /health, readiness: /ready}
    user: 10001
    metrics: /metrics
    volumes: {tmp: /tmp}
    env: {LOG_LEVEL: INFO}
    secretRefs: []
    secrets:
      - {name: todo-api-auth, generate: [JWT_KEY]}
      - {name: todo-api-stripe, remote: {keys: [STRIPE_KEY]}}   # path default "{system}-{env}-{secret}"
    replicas: 1                    # one number
    resources: {requests: {cpu: 50m, memory: 128Mi}, limits: {memory: 512Mi}}
    expose: {host: api}
    provides: [todo-api-rest]
    consumes: []
    uses: [postgres, todo-lib]     # resources and library components
    instances:                     # keys = environments it runs in; absent = dev only
      dev: {}
      staging: {promote: manual}
      prod: {replicas: 2, env: {LOG_LEVEL: WARN}, secrets: [{name: todo-api-stripe, remote: {keys: [STRIPE_KEY], path: "prod/{secret}"}}]}
  todo-lib: {type: library, lang: python, repo: acme/todo-lib}
  stock: {type: service, lang: unknown, repo: acme/stock, image: ghcr.io/acme/stock, external: {kustomize: external/stock}}

apis:
  todo-api-rest: {type: openapi}   # openapi | grpc | graphql | events

resources:
  postgres:                        # the only resource in 5.0
    type: database
    version: 17
    replicas: 1
    storage: 1Gi
    resources: {...}               # optional, as 4.x
    instances: {prod: {replicas: 3, storage: 20Gi}}   # per-env overrides: replicas, storage, resources
```

### Keys

| Where | Allowed keys |
|---|---|
| top level | `system`, `owner`, `environments`, `components`, `apis`, `resources`, `gateway`, `secretStore`, `registries` |
| `environments.<env>` | `host`, `url`, `policy`, `promote`, `observability` |
| service / website component | `type`, `lang`, `repo`, `image`, `port`, `probes`, `user`, `volumes`, `env`, `secretRefs`, `secrets`, `replicas`, `resources`, `expose`, `metrics`, `provides`, `consumes`, `uses`, `instances` |
| external component (`external:` present, spec 069) | `type`, `lang`, `repo`, `image`, `external`, `provides`, `consumes`, `instances`; an instance may set only `promote` |
| library component | `type`, `lang`, `repo`, `provides`, `consumes` |
| `components.<c>.instances.<env>` | `replicas`, `resources`, `env`, `promote`, `secrets` |
| `apis.<a>` | `type` |
| `resources.postgres` | `type`, `version`, `replicas`, `storage`, `resources`, `instances` |
| `resources.postgres.instances.<env>` | `replicas`, `storage`, `resources` |

Valid `type`/`lang` pairs: `service/python`, `service/java`, `service/go`, `website/typescript`, `library/python`, and `service/unknown` (migrated 4.x entries without a known shape). `render.py` holds them as a constant; `model.TYPE_LANGS` derives them from `shapes.yml` plus `service/unknown`; a platform test compares both.

### Semantics

- A component runs in exactly the environments that are keys of its `instances` (none = `dev` only); a library has none. Instance `env` is merged over the component's (instance wins); `replicas`, `resources` replace; `secrets` entries replace the top-level fields (`generate`, `length`, `remote`) of the declared secret of the same name in that environment only (AC-114.13, AC-114.18).
- `host` placeholders `{component}` (`expose.host` or the component name), `{system}`, `{env}`; `url` placeholders `{host}`, `{component}`, `{system}`, `{env}`; secret `path` placeholders `{system}`, `{env}`, `{secret}`, `{component}` (AC-114.5, AC-114.6, AC-114.17).
- `policy` maps to the 4.x modes `audit`→`Audit`, `enforce`→`Enforce`, `off`→`Off`. As in 4.x a guard-rail policy is rendered only for an environment that has an instance and a policy other than `off` (AC-114.7).
- `observability` on an environment gives that environment the collector (only when an instance runs there, as 4.x) and every instance there the `OTEL_*` variables; the allowed-registry list of that environment's policy adds the collector image (AC-114.9).
- `resources.postgres` is rendered in every environment where a running component uses it; cluster `instances` = instance `replicas` or `replicas` (default 1), `storage` likewise (default `1Gi`), `version` default 17 (AC-114.19).
- `promote` on `environments.staging` or `instances.staging`: `after-dev-smoke` is the 4.x `auto` of spec 093; the instance value wins.

### Render errors (`render.py`, printed as `ERROR: <text>`, exit 1, nothing written)

All messages start with `applications/<dir>/system.yaml: `. Exact texts after that prefix:

| Case | Text |
|---|---|
| unmigrated directory (AC-114.22) | the line is `ERROR: applications/<dir>: not migrated to 5.0: run `cplat platform update --migrate`` (checked for every directory before anything is rendered) |
| unknown top-level key | `unknown key '<k>' (allowed: system, owner, environments, components, apis, resources, gateway, secretStore, registries)` |
| `system` missing / different | `system is required (the directory is <dir>)` / `system '<value>' does not match the directory <dir>` |
| `owner` | `owner is required: a non-empty string` |
| environment list | `environments must be dev, staging, prod in this order (the promotion order), got <comma list or 'none'>` |
| environment key | `environments.<env>: unknown key '<k>' (allowed: host, url, policy, promote, observability)` |
| host placeholder | `environments.<env>.host: {service} is {component} in 5.0` / `{app} is {system} in 5.0` / `unknown placeholder {<x>} (allowed: {component}, {system}, {env})` |
| policy | `environments.<env>.policy must be audit, enforce or off, got '<v>'` |
| promote | dev: `environments.dev.promote: dev follows main and takes no promote`; staging: `environments.staging.promote must be after-dev-smoke or manual, got '<v>'`; prod: `environments.prod.promote: prod is always promoted by hand (manual), got '<v>'` (the same texts with `components.<c>.instances.<env>.promote` for an instance) |
| observability | the 4.x texts with `environments.<env>.observability` instead of `app.yaml: observability` |
| type/lang | `components.<c>: type and lang are required (valid: <pairs>)` / `components.<c>: <type>/<lang> is not a valid type/lang pair (valid: <pairs>)` |
| shape | `components.<c>: shape is replaced by type and lang in 5.0 (e.g. type: service, lang: python)` |
| environments / promotion / replicas map | `components.<c>: environments is replaced by instances in 5.0 (its keys are the environments it runs in)` / `components.<c>: promotion is replaced by instances.<env>.promote in 5.0` / `components.<c>: replicas is one number; per-environment replicas go under instances.<env>.replicas` |
| versions (AC-114.20) | `components.<c>: versions are pinned in the overlays, not in system.yaml (remove <tag \| version \| the tag of image>)` |
| unknown component key | `components.<c>: unknown key '<k>' (allowed: <keys of its kind>)`; external: `components.<c> is external: <k> belongs in its package, not in system.yaml` |
| library (AC-114.14) | `components.<c>: a library has no instances (remove <instances \| image \| port \| expose>)` |
| instances | `components.<c>.instances: '<k>' is not an environment (environments: dev, staging, prod)` / `components.<c>.instances.<env>: unknown key '<k>' (allowed: replicas, resources, env, promote, secrets)` / `components.<c>.instances.<env>.secrets: '<s>' is not a secret of <c> (declared: <names or none>)` |
| uses (AC-114.15) | `components.<c>: uses '<u>', which is neither a resource nor a library of the system (resources: <list or none>; libraries: <list or none>)` |
| APIs (AC-114.16) | `apis.<a>: type must be openapi, grpc, graphql or events` / `components.<c>: provides '<a>', which apis: does not declare` (consumes likewise) / `apis.<a>: provided by <n> components (<names or none>); an API has exactly one provider` |
| resources (AC-114.19) | `resources.<r>: 5.0 supports one database resource named postgres (type: database)` / `resources.observability: observability is set per environment under environments.<env>.observability` / `resources.postgres: unknown key '<k>' (allowed: type, version, replicas, storage, resources, instances)` |
| secrets | the 4.x secret checks with `components.<c>` instead of `service '<c>'`; a `path` with `{service}`/`{app}` gives the host texts with `secrets.<s>.remote.path` |

`render.py` exposes `ENVS` (unchanged), `load_system(app_dir) -> dict` (validated, normalized) and `render_app(app_dir, ans) -> dict[Path, str]` (unchanged signature); `scripts/pin.py` keeps calling `render_app`.

## Contract — the model (`model.py`, schema 2)

```python
SCHEMA = 2
NOT_MIGRATED = "not migrated to 5.0: run `cplat platform update --migrate`"
class NotMigrated(ModelError): ...                          # message NOT_MIGRATED, hint "this repo still has app.yaml/services.yaml (4.x)"
TYPE_LANGS: tuple[tuple[str, str], ...]                     # registry pairs + ("service", "unknown")
def type_lang(shape: str | None, shapes=None) -> tuple[str, str]   # 4.x shape -> (type, lang); None/unknown -> ("service", "unknown")
def shape_for(type: str, lang: str, shapes=None) -> str | None     # ("service","java") -> "service-java"; service/unknown -> None
def build(doc: dict | None, system: str, *, pins=None, shapes=None) -> Model    # doc = parsed system.yaml; lenient
def load_dir(app_dir) -> Model        # NotMigrated when app.yaml or services.yaml exists; else system.yaml (strict parse, ModelError naming it)
def load_remote(system, read) -> Model   # read("applications/<s>/system.yaml"); None and read(".../services.yaml") not None -> NotMigrated
```

`pin_path`, `pin_of`, `read_pin`, `write_pin`, `ENVIRONMENTS`, `DEFAULT_LOCAL_PORT` are unchanged. Nouns change as follows (everything else as spec 113):

- `Environment.policy` is `audit` | `enforce` | `off`; `Environment.promotion` is `main` (dev) | `after-dev-smoke` | `manual`. `Observability` gains `headers_secret`, `query_secret`.
- `Component` gains `provides`, `consumes`, `libraries` (used library names); `uses` stays resources only; `shape` = `shape_for(type, lang)`; `environments` = instance keys in promotion order (`("dev",)` when absent, `()` for a library); `promotion_staging` = `instances.staging.promote`.
- `Instance.replicas` = instance override, else component `replicas`, else 1 (None for external); `Instance.secrets` apply the instance's overrides, `InstanceSecret` gains `overridden: bool`; `store_key` = `(path or "{system}-{env}-{secret}").format(system=, env=, secret=, component=)`.
- `Model` gains `owner`, `apis: tuple[Api]` (`Api(name, type, provider: str | None, consumers: tuple[str, ...])`); `declared_addons` is removed; `ResourceInstance.sizing` is `{"replicas", "version", "storage"}`.
- URL rule: `host = host_template.format(component=(expose.host or name), system=, env=)`, `url = url_template.format(host=, component=, system=, env=)`, else the 4.x fallback.
- `Model.staging_promotion(c)` returns `after-dev-smoke` or `manual`.

### `cplat model show --json` (AC-114.69)

Schema 1 keys and meanings stay, with these changes: `"schema": 2`; `system` gains `owner` and `apis` (names); `environments[].policy` and `.promotion` use the 5.0 words; `environments[].observability` gains `headersSecret`, `querySecret`; `components[]` gain `provides`, `consumes`, `libraries`, `used_by` (the components that use a library; `[]` otherwise); a top-level `apis: [{"name", "type", "provider", "consumers"}]`; `instances[].secrets[]` gain `overridden`; `resource_instances[].sizing` has `replicas` instead of `instances`. Relations add `part_of` (api → system), `provides` and `consumes` (component → `api:<name>`), `uses` (component → library component). The 4.7 ↔ 5.0 comparison maps `Audit/Enforce/Off` → lowercase, promotion `auto` → `after-dev-smoke`, host/url placeholders as the migration does, and sizing `instances` → `replicas`; everything else must be equal.

### `cplat model show` (text)

As spec 113 with: a line `Owner: <owner>` after `System:`; environment lines `policy <audit|enforce|off>  promote <follows main|after-dev-smoke|manual>`; component lines end with `  provides <list or ->  consumes <list or ->  libraries <list or ->`; an `APIs:` section after Components, one line `  <name>  type <type>  provider <c or ->  consumers <list or ->`; Resource-instance sizing prints `replicas <n>`.

- A 4.7 name prints to stderr exactly `` `cplat <old>` is `cplat <new>` in 5.0 `` and exits 2 without importing the module (`compose` → `cplat component add|set|remove`, `addon` → `cplat resource add|remove`, `smoke` → `cplat instance verify`, `update-service` → `cplat platform update`).
- A noun without a verb, or an unknown verb, prints the noun's verbs and exits 2. `--help` prints the 5.0 usage block (the module docstring lists every noun line). `argparse` `prog` of each module is its 5.0 form (`cplat instance promote`, …).

### Command arguments that change

- `cplat component new <name> <description…> [--type service|website|library] [--lang python|java|go|typescript] [--system OWNER/REPO] …` (other flags as 4.7). Missing `--type` and `--lang` → `service`/`python`; one given → the other is its only or first registry partner (`website`→`typescript`, `library`→`python`, `service`→`python`; `java`/`go`/`python`→`service`, `typescript`→`website`). `unknown` and other pairs fail: `<type>/<lang> is not a valid component type (valid: service/python, service/java, service/go, website/typescript, library/python)`. 4.x flags fail (exit 1): `--web` → `` `--web` is `--type website --lang typescript` in 5.0 ``; `--library` → `` `--library` is `--type library --lang python` in 5.0 ``; `--gitops` → `` `--gitops` is `cplat system new <manifest>` (/system:new) in 5.0 ``; `--type <shape id>` → `` `--type service-java` is `--type service --lang java` in 5.0 ``; `--app` → `` `--app` is `--system` in 5.0 ``. A hidden `--shape <id>` (`argparse.SUPPRESS`) stays for `system new` and the platform's tests.
- `cplat system new <manifest>`: keys `system` (name), `owner` (required string), `org`, `visibility`, `components: [{name, description, type, lang, data}]`; `app` → `` `app` is `system` in 5.0 ``; a component `shape` → `component '<n>': shape is replaced by type and lang in 5.0`; `unknown` is refused. The gitops-app is created with `--shape gitops-app --data owner=<owner>`, then one `component add … --pr`.
- `cplat component add <component…> [--type T --lang L] …` (replaces `--shape`) writes `components.<name>` with `type`, `lang` and `instances: {dev: {}}`; `set <component> [--env K=V] [--expose [HOST]] [--uses NAME] [--replicas N] [--instance ENV]`, where `--instance ENV --replicas N` writes `instances.<ENV>.replicas` (`ENV` must already be an instance key, else `<c> has no instance in <ENV>`), `--instance` with anything but `--replicas` fails. PR branch `component/<action>-<names>`, title `feat(component): <action> <names>`. `--from-k8s` as 4.7.
- `cplat resource add postgres [--version N]` writes `resources.postgres: {type: database, version: 17, replicas: 1, storage: 1Gi, instances: {prod: {replicas: 3, storage: 20Gi}}}`; `remove postgres` refuses while a component uses it. `add observability` (exit 1, nothing written): `observability is set per environment under environments.<env>.observability in system.yaml`; any other name: `5.0 supports one database resource named postgres`. No `list`. PR branch `resource/<action>-postgres`.
- `cplat instance promote <component…|--all> --to <env> [--version vX.Y.Z] [--sha S] [--no-verify] [--accept-digest-mismatch R] [--system NAME] [--repo-dir D] [--pr] [--dry-run] [--json]`. Source = the environment before `<env>`. Errors (exit 1, nothing changed): no `--to` (also the 4.x `<from> <to>` form) → `promote names its target with --to: cplat instance promote <component...|--all> --to <env>`; `--to dev` → `dev is the first environment: nothing is promoted to it (dev follows main)`; unknown env → `unknown environment '<e>' (environments: dev, staging, prod)`; missing source instance → `<c> has no instance in <source> (it runs in: <envs>)`. It adds `instances.<env>: {}` (round-trip, comments kept), renders, writes the pin, renders again; prod keeps the spec 106 digest check. Output, JSON and PR as 4.7 with `component` for `service`.
- `cplat instance secret set <component>/<env> <secret> <KEY> [--value-stdin] [--system] [--repo-dir] [--context]` and `cplat instance secret list [--env dev] …`. The store key comes from the instance (overrides applied). A secret the component does not declare, or a `generate` secret: `<component> has no remote secret '<s>' (remote secrets: <names or none>)`. `list` hints `cplat instance secret set <c>/<env> <s> <KEY>`.
- `cplat instance verify [ENV] [--base-url URL] [--spec S] [--no-retry] [--json] [--repo D]` (ENV default `dev`; `--env` is accepted too). Without `--base-url` the URL comes from the linked system's model for any environment the component has an instance in (4.7 needed `--base-url` outside dev). ## Contract — migration (`cplat platform update --migrate`)

### When it runs (AC-114.44, AC-114.46, AC-114.47)

- A repo is unmigrated by the rule in Decisions. `platform update` without `--migrate` on an unmigrated repo: exit 1, `ERROR: this repo is on platform <old or none>: 5.0 changes its files and plugins` / `fix: run cplat platform update --migrate (or /platform:update --migrate)`.
- `--migrate` on a migrated repo: the normal update runs; the report says `already migrated` and nothing of the migration happens.
- `--migrate` on an unmigrated repo: the normal update (template, devbox, settings) plus the steps below, in one commit. A v1 repo still loses `k8s/`.

### Conversion (`migrate5.convert`, AC-114.41, AC-114.67)

`convert(system: str, app: dict, services: dict, owner: str | None, shapes=None) -> Conversion(doc: dict, problems: list[str], comments: bool)`; pure. `problems` are `"<file>: <dotted key> (<why>)"`; any problem stops the migration.

| 4.x | 5.0 |
|---|---|
| directory name | `system` |
| `.copier-answers.yml` `github_org` (fallback: owner of the `origin` remote) | `owner` (none found: problem `owner`) |
| `gateway`, `secretStore`, `policies.registries` | top-level `gateway`, `secretStore`, `registries` |
| `hosts.<env>`, `urls.<env>` | `environments.<env>.host`, `.url`; `{service}`→`{component}`, `{app}`→`{system}` |
| `policies` absent or `false` | `policy: "off"` on every environment |
| `policies.mode` (scalar or per-env map, default Audit/Audit/Enforce) | `policy` on every environment, lowercased |
| `promotion.staging: auto \| manual`; `promotion.prod: manual` | `environments.staging.promote: after-dev-smoke \| manual`; dropped |
| `addons.observability` (`null` = `{}`) | the same mapping as `observability` on every environment |
| `addons.postgres` | `resources.postgres` with `type: database`; scalar `version`, `instances`→`replicas`, `storage`, `resources` at the top; per-env map values under `instances.<env>` (`replicas`, `storage`); a per-env `version` map with different values is a problem |
| service entry | `components.<name>` with its keys in 4.x order; `shape` → `type`+`lang` (`model.type_lang`); `environments` → `instances` keys (`{}` each, `dev` when absent); `replicas` map → `instances.<env>.replicas`; `promotion.staging` → `instances.staging.promote`; secret `path` placeholders converted |
| anything else (other top-level keys, other addons, a `replicas`/`promotion` value for an environment the service does not run in, unknown environment names, v1 entries without `port`/`probes`, other entry keys) | a problem |

`dump(doc) -> str` writes `yaml.safe_dump(doc, sort_keys=False, default_flow_style=False)` after this header (AC-114.48):

```yaml
# system.yaml of the <system> system: the only hand-edited file of this system (sdlc-foundry 5.0).
# Schema: https://github.com/ika100/sdlc-foundry/blob/main/docs/DOMAIN-MODEL.md#one-file-per-system
# Written by `cplat platform update --migrate` from app.yaml and services.yaml; their comments were not carried over.
```

Key order: `system`, `owner`, `gateway`, `secretStore`, `registries`, `environments`, `components`, `resources` (absent keys left out).

### Steps of a gitops-app migration (AC-114.40, AC-114.42)

1. Before anything changes: convert (problems → exit 1, nothing changed); copy `HEAD` to a temp dir, put `scripts/cplat/assets/render_v4.py` at its `scripts/render.py`, run it there, keep every file under `applications/<system>/` (minus `app.yaml`, `services.yaml`) and `bootstrap/`.
2. On the review branch: the template update, then write `system.yaml`, delete `app.yaml` and `services.yaml`, run the repo's (5.0) `scripts/render.py` through `gitops.render`.
3. Compare path → bytes with step 1 (minus `system.yaml`). Any difference: restore the tree (`git reset --hard`, `git clean -fd` of the branch), return to the original branch, delete the review branch, exit 1 with `ERROR: cannot migrate applications/<s> to 5.0: the 5.0 render differs from 4.7:` and one line per file (`<path> (changed|missing|extra)`), `fix: nothing was changed; report it with /issue:report`.
4. Otherwise continue with the update's commit.

A component repo (AC-114.46) only gets the template update and the plugin switch.

### Plugin switch (`settingsmerge`, AC-114.45)

`enabledPlugins` is merged, not replaced: the template's map (5.0 gitops-app: `system`, `component`, `api`, `resource`, `instance`, `issue`, `platform`, `svc`, `shared`; component repos: `component`, `api`, `instance`, `issue`, `platform`, `svc`, `shared` and the language plugin), plus every entry of the repo's map that the template lacks, minus `app@sdlc-foundry` and `gitops@sdlc-foundry`. It never counts as a replaced setting. `merge_settings` returns `plugins: {"added": [...], "removed": [...]}` (relative to the repo's previous map).

### Report (text and `--json`)

`did` lines (gitops-app): `wrote applications/<s>/system.yaml (the comments of app.yaml and services.yaml were not carried over)` (the parenthesis only when the old files had comments), `deleted applications/<s>/app.yaml, applications/<s>/services.yaml`, `the 5.0 render is byte-identical to 4.7 (<n> files compared)`; every repo: `plugins added: <list>; removed: <list>`. `Report.data["migration"]` = `{"ran": bool, "kind": "system" | "component", "byte_identical": true | null, "compared": int, "system_yaml": path | null, "deleted": [...], "plugins": {"added", "removed"}, "comments_dropped": bool}`; `{"ran": false, "already_migrated": true}` for an already migrated repo.

`--dry-run --migrate` (AC-114.43) prints, after the 4.7 plan lines: `would write applications/<s>/system.yaml:` and the full text indented by four spaces, `would delete <paths>`, `plugins: would add <list>; would remove <list>`, and changes nothing.

### Fleet (AC-114.49, AC-114.68)

`fleet_pr._run_update` adds `--migrate` when the repo's platform is below 5 and the target is 5 or more. The major-version reason of `pre_wait_reasons` is dropped when `data["migration"]["ran"]`, the old major is 4, the target major is 5, `lost` is empty and (`kind == "component"` or `byte_identical is True`). A failed migration raises before the push, so the row is `failed` with the error's first line and no PR. `fleet update --dry-run` says `5.0 migration: merges on green CI when proved` instead of `major version: the PR will stay open` for 4 → 5.

## Alert poll per environment (AC-114.10)

`alertsources.load_app(app_dir) -> AppConfig` keeps its name; `AppConfig` gains `sources: list[EnvSource]`, where `EnvSource(env, rules, prometheus_url, alertmanager_url, query_secret, notes, skip)` is built per environment in promotion order that has an instance and `observability`, with that environment's `rules`, `queryURL`, `alertmanagerURL`, `querySecret`, `ui`, `exportTo` (the 4.x skip reasons per source, prefixed with the environment). `ServiceDown` is added per instance of that environment whose component has `metrics`, unless that environment's rules define it. A bare `querySecret` name resolves in the namespace of the first environment with an instance, as 4.x did. `collect` evaluates each source and keeps a series only when it maps to that source's environment; a series that maps to no environment is kept once, by the first source. `AppConfig.skip` is set when no source remains (`no environment declares observability`, or each source's reason). `alerts.poll` reconciles all alerts of a system once, as before.

## Risks

- **Per-environment values for environments a 4.x service did not run in** (for example `replicas: {dev: 1, prod: 2}` on a dev-only service) have no place in 5.0 and stop the migration as unconvertible keys; the fleet reports such repos failed and the owner removes the value (or promotes first). This is the price of keeping instances exact.
- **Duplicate queries**: when every environment shares one Prometheus, rules run once per environment; the results are filtered by environment, so the issues equal 4.x.
- **Suite churn**: many existing tests build `services.yaml` fixtures or call the 4.x names. The plan ports them in the last two tasks; intermediate merges may leave unrelated old tests red.
- **`ruamel` vs `PyYAML` on `off`**: handled as described in Decisions; tests cover both spellings.
- **AC-114.56 without GitHub**: the cluster test cannot run a Claude session. It "ships a spec" with the deterministic steps: `cplat spec new` + `approve` in the component repo, `cplat component ship start`, the image build and apply it already does, `cplat instance verify dev --base-url`, `cplat instance promote <c> --to staging --sha <sha> --no-verify` with a staging render and apply, `cplat instance verify staging --base-url`, `cplat component ship finish`.
