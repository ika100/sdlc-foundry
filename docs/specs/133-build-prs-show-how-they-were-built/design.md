# Design — 133 Build PRs show how they were built

ADR: [079](../../adr/079-a-pr-shows-how-it-was-built-from-the-run-records.md).

## Decisions

1. **One new module, `scripts/cplat/runs_built.py`.** It finds a run record on this machine, collects the facts and renders the
   block. `runs.py` only adds the `--pr` option and a dispatch; `pr_open.py` calls one function. This keeps the change out of the
   aggregate functions of `runs_report.py` that spec 131 extends.
2. **Local records only.** The record is the active record (`runs.active`), else the newest buffered record with that `run_id`
   (`runs._read_buffer`). The runs it resumes (`resumes`, followed while found locally, at most 10) add wall time and decisions.
3. **The block is generated text between markers.** `<!-- cplat:how-built -->` … `<!-- /cplat:how-built -->` lets `cplat pr open`
   replace an earlier block. Inside: a collapsed `<details>` with four `####` headings in a fixed order.
4. **Redaction once, at rendering.** Every value that comes from a record or a file goes through `feedback.redact` (the same
   redaction as the run records and `/issue:report`) and is cut to 200 characters. Lists keep 10 lines, then `… and <n> more`.
5. **Sequential fallback is recorded by a new agent call** `cplat platform runs agent execution parallel|sequential [--reason R]`
   (section `execution`), because no record holds it today. Recording never fails a build (exit 0, as the other agent calls).
6. **`cplat pr open` never fails because of the section.** Any exception is caught; the body stays as it was and one `note:` line
   says why.

## Contract

### `cplat platform runs report --pr <run-id> [--dir D]`

Exit 0 and the block on stdout; exit 1 (PlatformError) for an unknown run or a combination with `--agents`, `--benchmarks`, `--json`,
`--since` (other than the default) or `--repo`. `--dir` (default `.`) is the repo whose `docs/specs/<spec>/` is read. Needs no
`CPLAT_RUNS_REPO`.

```markdown
<!-- cplat:how-built -->
<details><summary>How this was built</summary>

_Generated by `cplat platform runs report --pr 20261103T101500Z-ab12cd34` from the run's local records: no prompts, no diffs._

#### How it ran
- run 20261103T101500Z-ab12cd34 (build), wall time 1h 12m over 2 runs
- tasks: sequentially (worktree base is 1a2b3c4, not the feature head)
- re-plans: 1 · CI rounds: 2 · reruns: 1
- gates: acceptance passed · security passed
- budget: minutes 72 of 180 · invocations 14 of 60 · reruns 1 of 6 · cost $12.40 of $15
- agents: svc:architect, svc:coder, svc:reviewer, svc:tester

#### User decisions
- budget cost raised from 15 to 30
- stopped for a decision: <reason> (run <id>)
- test-diff refused `tests/test_x.py` (task t3): <reason>
- user-approved test changes: not recorded (#324)
- open questions answered in spec.md: 3

#### Hand-backs and fix rounds
- t3 → svc:coder: lint/type
- red CI: e2e → svc:coder
- finding AC-133.4 (not met, cycle 1) → svc:coder
- tester: AC-133.2 untraced
- merge conflict t4 with t2: re-planned
- re-plan t4 → svc:architect

#### Deviations the reviewer accepted
- `tests/x.py` is in no task's `files`.

</details>
<!-- /cplat:how-built -->
```

Values that are not recorded read `not recorded`; empty lists read `none` (`none recorded` for decisions, `none listed` for
deviations, `no verification.md yet` without the file).

### The `execution` section (AC-133.9)

`{"mode": "parallel" | "sequential", "reason": str | null}` at the top of the run record, set by
`runs_agents.execution(run_id, mode, reason=None)`. A bad mode marks the agent metrics incomplete (as other malformed calls) and
records nothing.

### The hook for #324: `approved_test_diffs`

A list at the top of the run record; each item `{"file": str, "task": str | null, "reason": str | null}`. Present (also empty) means
recorded: each item is one decision line `test change approved `<file>` (task <task>): <reason>`; absent means
`user-approved test changes: not recorded (#324)`.

### Sources

| Line | Source |
|---|---|
| wall time | `started_at` → `ended_at` (or now), over the record and the local records it `resumes` |
| tasks | `execution` |
| re-plans | `replans` (length) |
| CI rounds, reruns | `ci_rounds`, `reruns` (with their `check` and `reason`) |
| gates | `gates` |
| budget | the ledger whose `roots` holds the run (`budget._all()`), `budget.used_of`; limit changes from its `changes` |
| agents | `agents[].agent` |
| decisions | `escalation` with cause `decision` (this run and resumed ones); `refused-test-diff` events; `approved_test_diffs`; spec.md `Answered` lines |
| hand-backs | `fix-round`, `red-ci`, `finding`, `tester`, `merge-conflict`, `re-plan` events of `agents[]` |
| deviations | `docs/specs/<spec>/verification.md`, `## Deviations from the plan`, top-level items saying acceptable/accepted and not `not acceptable` |

### `cplat pr open`

After the WIP note and before the commit: `runs_built.pr_section(repo, spec)` returns the block or None. None → the body is not
touched. A block → an earlier marked block is replaced, else the block is appended after one blank line. The run is
`runs.current_run(repo)`; a run whose `spec` differs from `--spec` (compared by the leading number) is ignored.

## Risks

- A run's live cost needs the session transcripts (`runs_usage`); `used_of` reads them with its own 3 s budget and the result may be
  `unknown`. The block then says so.
- `verification.md` is free text; the deviation parser only reads the documented section and falls back to `none listed`.
