# Ship: a red or failed `cplat component ship land`

Read from `/component:ship` Phase `land` when `cplat component ship land` exits non-zero.

- **RED** (exit 1) → `cplat component ship land` records the round against the coder itself, so there is no `cplat platform runs agent` call here. Hand its failure summaries and log paths to the coder agent (`agents.coder`) of the task whose files are involved, with `<project-map>`: "fix these CI failures from the summary; the full log is for when the summary is not enough. **Hard rule:** never edit, skip or weaken an acceptance test, because it is the spec". Run `cplat validate run` (the checks the fix can affect; the whole `devbox run ci` runs in `cplat component ship pr` before every push), commit `fix(ci): <what>`, run `cplat spec test-diff $RED --task <task>`: a `test helper` or `type-only` line → the last paragraph of `build-tighten.md`, never a question, since the check refuses a dropped assertion; exit 1 otherwise → escalate cause `decision` as a changed test; then `cplat component ship pr --title <same title> --body-file .pr-body.md` (pushes) and `cplat component ship land` again. After **3** red rounds (`fix_rounds` in `cplat component ship status`), escalate with the last failure.
- **RED, the security check** → other red checks go to the coder first. Then `cplat deps patch`: exit 0 → `cplat deps report --body-file .git/PR_BODY.md --update-pr`, `cplat component ship pr` and `cplat component ship land` as above; exit 3 → `cplat component ship escalate '<reason>' --cause <CAUSE>` with the `ESCALATE` and `CAUSE` lines it printed; exit 4 → the coder. The round counts toward the 3.
- An error → read its hint; a transient one (runner busy) → `cplat component ship land` once more; otherwise escalate.
