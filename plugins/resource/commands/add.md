Run in the gitops-app repo. **Request:** $ARGUMENTS

A rule marked **Hard rule:** is never departed from. Any other rule is a practice: where its stated purpose does not apply, depart from it and name each departure and its reason in one line of your report.

```bash
cplat resource add <ARGS>
```

1. **Preview** with `--dry-run` and show it verbatim; errors carry a `fix:` line.
2. **Run** with `--pr` (one PR); do not ask again, because the user asked for it.
3. **Wait** once the PR is merged (merge it with `cplat pr wait <pr> --merge` when the user asked) and a component uses the resource: `cplat system wait --env <env> --refresh` for each environment with an instance of it, `--refresh` right after a merge you made (without it when the user merged). It ends `READY:` (exit 0), `RED:` (exit 1: a sync error, failed sync or `Degraded` at the new revision; show its lines and stop, nothing is retried) or `TIMEOUT:` (exit 2: run the same wait again, the command it prints, at most twice; then escalate with cause `environment`: `cplat component ship escalate '<the TIMEOUT line>' --cause environment` inside a ship run, otherwise report the `TIMEOUT:` lines to the user as an environment problem). Never write a polling loop on `kubectl`, `gh` or `cplat`, because the wait already ends on the synced revision.
4. **Next**: components opt in with `/component:set <component> --uses <name>`, which injects `DATABASE_URL` and `PG*` (database), `S3_*` and `AWS_*` (bucket), `REDIS_*` (cache) or `NATS_*` (broker: no `--uses`, an events API binds it). Relay the next steps `cplat` prints.

A resource has a name (lower-case letters, digits and `-`) and a type: `database`, `bucket`, `cache` or `broker`. `/resource:add postgres` without `--type` adds a database; any other name needs `--type`. A name that exists or is invalid changes nothing.

- **Prefix rule**: a component that uses two or more resources of one type gets that type's variables once per resource, prefixed with the upper-cased name (`ORDERS_DB_DATABASE_URL`, `USERS_DB_PGHOST`), and no unprefixed variable of that type.
- **`--version N`**: the supported database majors are 15, 16, 17 and 18; another major fails the render.
- **Bucket**: eight variables per used bucket: `S3_ENDPOINT`, `S3_BUCKET`, `S3_REGION`, `S3_FORCE_PATH_STYLE`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_REGION`, `AWS_ENDPOINT_URL_S3` (`UPLOADS_S3_BUCKET` with two or more buckets). `--storage S` sets the size (default `10Gi`); `--versioning` keeps object versions (default off). An in-cluster bucket is its own SeaweedFS per instance. With `--external` the store holds the six keys `endpoint`, `bucket`, `region`, `forcePathStyle`, `accessKeyId`, `secretAccessKey`; `--storage` and `--versioning` are ignored there.
- **Cache**: Redis-compatible, run as Valkey (`version: 8` or `9` in `system.yaml`, default 9; `--version` is for databases). `--type redis` or `valkey` is answered with `cache`. Keys: `memory` (default `256Mi`, at least `64Mi`), `maxmemoryPolicy` (default `allkeys-lru`), `persistence` (default `false`; `true` adds an append-log file on a `storage` volume, default `1Gi`). Four variables per used cache: `REDIS_URL`, `REDIS_HOST`, `REDIS_PORT`, `REDIS_PASSWORD` (the Secret's `url`, `host`, `port`, `password`; prefixed like the others with two or more caches, e.g. `SESSIONS_REDIS_URL`). With `--external` the store holds the four keys `url`, `host`, `port`, `password` (use a `rediss://` URL for providers that require TLS); the `url` of an in-cluster cache is `redis://default:<password>@<host>:6379/0`, which works unchanged with client libraries and with `valkey-cli` or `redis-cli -u`; with an external store, name the default user in `valkey-cli` or `redis-cli -u` (`redis://default:<password>@…`), since they read `redis://:<password>@` as an empty user name; sizing keys are ignored there. A cache needs no operator, and cache data is not backed up (with or without `persistence`). Changing `persistence` or `storage` of a running cache: `kubectl delete statefulsets.apps <system>-<name> -n <system>-<env> --cascade=orphan`, then sync (the pod restarts; an existing volume is reused, not resized).
- **Broker**: NATS with JetStream (spec 119). `--version V` is the NATS minor line, `2.14` or `2.15` (default `2.15`), `--replicas N` the server count (default 1; 3 for a cluster). There is no `--storage` for a broker (`cplat` refuses it): set `storage` in `system.yaml` (default `1Gi`). A component gets a broker without `--uses`: an `events` API is bound to it with `apis.<api>.broker: <name>` (implicit when the system has a single broker; with none, an unbound events API gets a note), and a component that provides or consumes the API gets it. It gets `NATS_URL`, `NATS_USER` and `NATS_PASSWORD` from its own Secret `<system>-<name>-<component>-app`; `NATS_INBOX_PREFIX` and one stream variable per events API, e.g. `EVENTS_ORDERS_STREAM`, are literal values. With `--external` the store holds the keys `url`, `user`, `password` under the path with `{component}` replaced by the component name (default `<system>-<env>-<name>-{component}`, or `--path P`); the render (`devbox run render`) prints the streams and consumers the owner creates.
- **`--external [--path P]`**: the database is not run by the platform; its connection data comes from the secret store. Tell the user to put the keys `uri`, `host`, `port`, `dbname`, `user`, `password` in the store under the key `cplat` prints (default `<system>-<env>-<name>`, or `--path P`). It needs a secret store in the system.
- **Operator**: an in-cluster database needs CloudNativePG and an in-cluster bucket needs the SeaweedFS operator, an in-cluster broker needs NACK, which the platform installs through `operators/`. Apply `operators/root.yaml` once per cluster (`KUBE_CONTEXT=<ctx> devbox run bootstrap`; `devbox run cluster-up` does it locally). An environment that sets `operators: owner` has the operator installed by its owner.

Observability is not a resource: it is set per environment under `environments.<env>.observability` in `system.yaml`; `resource add observability` exits 1 and says so. Removing a resource leaves the database, bucket or broker data in place. No backups, PITR or pooling are provided (ADR-020).

Read `cplat`'s output whole, never through `grep`, `head` or `tail`, because its last lines carry the decisions and fixes; use `--json` where offered.

> If a platform template, script or command misbehaves (not the user's code), stop, summarize it in two lines and offer `/issue:report`. **Hard rule:** never file an issue without the user's OK, because the platform repository is public; a `platform` escalation is the one issue the platform files itself (ADR-033).
